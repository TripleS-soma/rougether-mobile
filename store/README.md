# 스토어 리스팅 문구

App Store Connect / Google Play Console에 올리는 **텍스트 메타데이터의 단일 출처**입니다.
각 파일의 내용이 곧 콘솔 입력값입니다 — 주석이나 머리말을 넣지 마세요.

## 왜 저장소에 두는가

문구가 콘솔에만 있으면 **코드에서 기능을 지워도 리스팅이 그대로 남습니다.** 실제로 그랬습니다:

- 사진 인증 UI 제거 (#695, #712)
- 인앱 도움말에서도 제거 (#797) — 커밋 메시지가 "앱에 없는 기능이다"
- **스토어 설명에는 "사진 인증 루틴으로 진짜 했는지 확인하고"가 그대로 남음** (2026-08-14 발견)

App Store 심사 가이드 **2.3(정확한 메타데이터)** 위반이고, 리뷰 대상이 아니었기 때문에 아무도 못 봤습니다.
이제 여기 있으니 기능 제거 PR의 diff에 함께 걸립니다.

## 구조

```
store/ko-KR/
  app-store/
    name.txt              앱 이름            ≤ 30자
    subtitle.txt          부제               ≤ 30자
    promotional-text.txt  프로모션 텍스트     ≤ 170자
    keywords.txt          키워드             ≤ 100자 (쉼표 포함, 쉼표 뒤 공백 금지)
    description.txt       설명               ≤ 4000자
    release-notes.txt     새로운 기능         ≤ 4000자
  play/
    title.txt             제목               ≤ 30자
    short-description.txt 간단한 설명         ≤ 80자
    full-description.txt  자세한 설명         ≤ 4000자
```

`store/__tests__/metadata-limits.test.ts`가 글자 수 상한과 "앱에 없는 기능 홍보 금지"를
검사합니다. `npm test`에 포함되므로 CI가 자동으로 막습니다.

## 반영 절차 (수동)

자동 업로드는 없습니다 — 콘솔에 사람이 붙여넣습니다.

1. 여기서 문구를 고치고 PR → 머지
2. App Store Connect / Play Console에 붙여넣기
3. 아래 동기화 표의 상태·날짜 갱신

**App Store 주의**: 이름·부제·키워드·설명·스크린샷은 **버전에 묶입니다.** 심사 중인 버전이
있으면 수정할 수 없고, 심사에서 내리거나(순번 초기화) 다음 버전 제출 때 함께 올려야 합니다.
**프로모션 텍스트만 언제든 바꿀 수 있습니다** — 급한 공지는 이 칸을 쓰세요.

## 정책 문서는 여기 없다 — 다른 레포다

개인정보처리방침·이용약관은 이 저장소가 아니라 **`TripleS-soma/rougether-landing`의
`public/privacy.html` · `public/terms.html`** 에 있습니다(main 푸시 = 즉시 배포).
`TripleS-soma/policy`는 옛 주소용 리다이렉트 스텁만 남아 있으니 건드리지 마세요.

그래서 **기능을 바꿔도 이 저장소 diff에 안 걸립니다.** 1.2.0의 기기 캘린더 읽기가
방침에 한 줄도 없이 심사 직전까지 갔습니다(#905). 새 권한을 요구하거나 서버로 보내는
데이터가 늘면 `AGENTS.md`의 "새 데이터·새 권한을 만지면 정책 문서도 고친다"를 따르세요.

## App Privacy (App Store Connect 설문) — 코드가 못 막는 곳

리스팅 문구와 달리 **App Store Connect의 App Privacy 설문은 이 저장소에 사본이 없습니다.**
기능이 새 데이터를 만지면 사람이 콘솔에서 갱신해야 하고, 어긋나면 심사 거부 사유입니다.

- **1.2.0에서 캘린더 읽기가 추가됐습니다** (#844). 기기 캘린더의 **일정 제목과 날짜**를 읽어
  사용자가 고른 것만 서버에 할 일로 저장합니다. 캘린더에 쓰지 않고, 일정을 통째로 동기화하지도
  않습니다. 제출 전에 App Privacy에서 해당 데이터 유형(사용자 콘텐츠 계열) 수집 여부를
  실제 동작과 **대조**하세요. 할 일·루틴 제목으로 "사용자 콘텐츠"가 이미 신고돼 있으면
  출처만 늘어난 것이라 라벨은 그대로일 수 있습니다 — 바꾸기 전에 현재 값을 먼저 볼 것.
- 권한 문구(`NSCalendarsUsageDescription`)는 `app.json`의 `expo-calendar` 플러그인 설정에
  있고, `plugins/with-calendar-readonly.js`가 쓰기 권한을 떼어냅니다 — 심사자가 "읽기만
  한다"는 설명과 실제 권한이 일치하는지 봅니다.

## 서명 인증서·키 해시 — 소셜 로그인이 여기에 달려 있다

**Play가 AAB를 자기 키로 재서명한다**(Play 앱 서명). 업로드한 파일의 서명과 사용자
기기에 깔리는 서명이 **다르다**. 소셜 로그인 SDK는 실행 중인 앱의 서명을 콘솔 등록값과
대조하므로, 업로드 키만 등록해두면 **Play로 깐 설치본만 로그인이 통째로 실패한다**
(2026-08-22, 안드로이드 배포본 전건 실패로 확인).

증상은 SDK마다 다르게 나온다 — 구글은 `DEVELOPER_ERROR`(코드 `10`), 카카오는
`misconfigured`. 둘 다 "서명이 등록 안 됨"의 다른 표현이다.

| 인증서       | SHA-1                                                         | 카카오 키 해시                 | 어디에 깔린 설치본         |
| ------------ | ------------------------------------------------------------- | ------------------------------ | -------------------------- |
| Play 앱 서명 | `78:BF:C7:A5:B0:41:3B:63:17:AF:90:3A:3E:E5:24:27:33:03:00:83` | `eL/HpbBBO2MXr5A6PuUkJzMDAIM=` | **Play 스토어·내부테스트** |
| 업로드 키    | `BB:C1:09:DA:6F:1E:6E:2B:0C:9E:69:22:5C:4A:1F:0E:C9:24:76:ED` | `u8EJ2m8ebisMnmkiXEofDskkdu0=` | EAS 링크 직접 설치         |

**둘 다 등록해야 한다.** 하나만 넣으면 다른 경로로 깐 기기에서 로그인이 안 되는데,
개발자는 보통 EAS 링크로 깔아 테스트하므로 **Play 쪽 누락을 못 느낀다.**

등록처 (패키지명은 양쪽 다 `com.triples.rougether`):

- **구글** — 클라우드 콘솔 **프로젝트 `499923665503`(rougether)** → OAuth 클라이언트 → Android.
  파이어베이스 프로젝트(`437063052004`)가 **아니다.** 앱은 `webClientId`를 JS에서
  넘기고(`src/lib/google-auth.ts`), 네이티브는 그 값만 읽는다
  (`RNGoogleSigninModule.java:129` — `google-services.json`의 `default_web_client_id`로
  떨어지는 폴백 경로가 없다). 검증 주체는 **webClientId가 속한 프로젝트** 하나뿐이다.
  변경 전파에 최대 몇 시간 걸릴 수 있다.
- **카카오** — 개발자 콘솔 → 내 애플리케이션 → 플랫폼 → Android → 키 해시.
  키 해시는 SHA-1 바이트를 base64로 옮긴 값이다:
  `python3 -c "import base64;print(base64.b64encode(bytes(int(x,16) for x in '<SHA-1>'.split(':'))).decode())"`

**Play 앱 서명 SHA-1 확인**: Play Console → 설정 → 앱 서명 → "앱 서명 키 인증서".
같은 화면의 "업로드 키 인증서"와 헷갈리기 쉬우니 제목을 확인할 것.

**배포본이 실제로 어느 키로 서명됐는지 확인**(JDK 없이):
`unzip -p app.aab 'META-INF/*.RSA' | openssl pkcs7 -inform DER -print_certs | openssl x509 -fingerprint -sha1 -noout`

## 알려진 ASO 과제

2026-08-14 감사에서 나온 것들. 심사 통과 후 다음 버전에 함께 반영합니다.

- **이름이 30자 중 3자만 사용** — `루게더`는 조어라 검색량이 없다. 이름 필드는 한국
  App Store에서 검색 순위 가중치가 가장 크다. `루게더 - 루틴 습관 트래커` 형태 검토.
- **부제 16/30자** — `루틴`·`습관`은 들어갔고 여유가 있다.
- **스크린샷 5장이 캡션 없는 원본 캡처** — 재화가 `9999+` 디버그 값이고, 루틴 이름이
  `루게더 개발`·`소마 정기 회의`이며, 테마도 현재(분홍)와 다른 초록 계열이다.
  (스크린샷은 이 폴더가 아니라 콘솔에서 관리한다 — 파일이 커서 저장소에 두지 않음)
