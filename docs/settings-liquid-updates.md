# 설정 리퀴드 디자인과 수동 OTA 적용 (#1082)

설정 첫 카드에서 현재 설치 앱과 호환되는 OTA를 확인하고 다운로드한 뒤, 사용자가 원할 때 앱을 다시 시작한다. 스토어 바이너리 업데이트를 대신하거나 채널·런타임 제한을 우회하지 않는다.

## 동작

- `업데이트 확인` → 확인 중 → 다운로드 중 → `지금 적용` 순서다. 다운로드만으로 앱을 재시작하지 않는다.
- `지금 적용`은 저장하지 않은 작업에 대한 안내와 재시작 확인창을 연다. `나중에`·바깥 영역·Android 뒤로 가기는 취소한다. 확인 버튼에서만 `Updates.reloadAsync()`를 호출한다.
- Expo가 시작 시 이미 받아 둔 업데이트도 `useUpdates().isUpdatePending`을 통해 `지금 적용`으로 표시한다. 기존 시작 시 자동 다운로드 정책은 유지한다.
- 확인·다운로드·재시작 중 중복 요청을 막는다. 네트워크 실패는 재시도할 수 있고, 재시작 요청 실패 후에는 다운로드 완료 상태를 유지한다.
- 서버가 지시한 기본 코드 롤백도 다운로드 완료 후 확인을 거친다. 이 기기에서 이전에 실행에 실패한 업데이트는 강제로 재적용하지 않는다.
- 새 OTA가 없으면 **현재 앱과 호환되는 새 업데이트가 없음**이라고 표시한다. 스토어 버전까지 최신이라고 단정하지 않는다.
- 웹·개발 빌드·Expo Updates 비활성 환경에서는 동작을 막고 이유를 표시한다.
- `업데이트 정보`에서 실행 중인 앱 버전·채널·런타임·업데이트 ID·기본 코드 여부를 확인하고 복사할 수 있다. 긴 식별자는 좁은 화면에서 줄바꿈한다.

## 구조와 디자인

- `use-app-updates.ts`: Expo의 네이티브 업데이트 상태를 관리한다. 비즈니스 API나 react-query 캐시와 별개다. 화면에 주는 상태와 콜백의 참조 안정성을 유지한다.
- `app-update-card.tsx`: 상태와 콜백만 받는 순수 UI. 확인창과 진단 정보 펼치기를 담당한다.
- `use-settings-surface.tsx`: 실제 업데이트 훅을 설정 화면에 연결한다.
- 설정 카드·아이콘·모드 선택에 기존 `GlassSurface`와 테마 토큰을 재사용한다. iOS 지원 환경의 네이티브 글래스, Android·웹·구형 iOS의 반투명 대체 표현, 투명도 줄이기의 불투명 표현은 공용 컴포넌트 정책을 따른다.
- 기존 계정·알림·약관 메뉴와 로그아웃·탈퇴의 확인 절차는 유지한다. 개인정보·권한·서버 API·네이티브 의존성·앱 설정은 변경하지 않는다.

## 미리보기와 검증

`npx expo start --web --port 8082` 후 `/dev-settings`에서 상태를 골라 확인한다. Dev 갤러리에도 같은 미리보기가 등록된다.

이 화면은 **실제 OTA나 비즈니스 API를 호출하지 않는 개발 전용 픽스처**다. 적용 확인 횟수만 증가한다. production에서는 홈으로 이동하며 시뮬레이션을 렌더하지 않는다.

자동 테스트는 업데이트 확인·다운로드·실패·중복 요청·기본 코드 롤백·재시작 확인, 실제 설정 배선, 개발 라우트 가드, 기존 메뉴 동작을 검증한다. 전체 테스트 외에 iOS·Android·웹 export 및 양 플랫폼 네이티브 지문을 확인한다.

실기기 릴리스 확인 항목:

1. 호환되는 채널·런타임의 설치 앱에서 설정 → 업데이트 확인 → 다운로드 완료까지 기다린다.
2. `나중에`는 재시작하지 않고, `지금 적용` 확인은 앱을 다시 시작하는지 확인한다.
3. 다시 열린 설정의 `실행 중 업데이트`가 배포된 ID로 바뀌었는지 확인한다. 로그인과 저장된 사용자 설정 유지도 확인한다.
4. 오프라인에서는 재시도 안내, 새 OTA가 없으면 호환 업데이트 없음 문구를 확인한다.
5. iOS 네이티브 글래스·Android 대체 표현·투명도 줄이기·큰 글자에서 카드와 확인창을 확인한다.

웹 픽스처와 네이티브 SDK 모의 테스트는 실제 기기의 다운로드·재시작 성공 증거가 아니다. 실제 OTA 발행 및 스토어 운영은 [배포 런북](release-ops.md)을 따른다.

## 최초 도달 한계

이 버튼도 앱 코드이므로 **기존 설치 앱이 이 변경을 포함한 OTA 또는 새 스토어 빌드를 먼저 받아야** 사용할 수 있다. 아직 이 코드를 받지 못한 앱을 원격으로 강제 재시작하거나, 다른 런타임의 업데이트를 받게 만들 수 없다. 이후 호환 OTA에 대해 사용자가 설정에서 직접 확인·적용할 수 있도록 하는 기능이다.
