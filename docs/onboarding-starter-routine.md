# 관심사 기반 첫 루틴 (#1148)

관심사·캐릭터·닉네임 선택을 마친 신규 사용자는 추천 화면에서 첫 루틴 한 개를 바로 만들 수 있습니다. 기존 등록 화면을 다시 작성하지 않습니다.

- 목표 마스터의 `code`로 작은 루틴을 매칭합니다. 여러 관심사면 하나씩 번갈아 세 개를 보여줍니다. 알 수 없는 코드는 일반 시작 루틴으로 대체하며 맞춤 추천이라고 표시하지 않습니다.
- 사용자가 카드 하나를 선택하고 `이 루틴으로 시작하기`를 눌렀을 때만 기존 `POST /routines`를 호출합니다. 기본값은 `CHECK`, `DAILY`, 알림 시각 없음, 종료일 없음입니다. 시작일은 서버의 KST 오늘 기본값을 사용합니다.
- 기존 카테고리 중 이름이 맞는 항목을 사용합니다. 없으면 서버가 허용하는 미분류로 등록합니다. 추가 카테고리 입력을 요구하거나 집에 자동 연결하지 않습니다.
- 등록 직후 앱 셸을 새로 열어 서버의 오늘 루틴을 조회합니다. 신규 온보딩의 4단계 미션 배너·완료 시트는 자동 시작하지 않습니다. 설정의 튜토리얼 다시 보기에서 기존 미션 체인은 사용할 수 있습니다.
- `나중에 할게요`는 루틴을 만들지 않고 앱으로 이동합니다. 해당 계정에 같은 추천 화면을 강제하지 않습니다.
- 단계 진행은 계정별 `rougether.starter-routine.v1.{userId}`에 저장합니다. 같은 기기에서 중도 종료하면 재개하며, 재개/등록 전에 기존 루틴이 있으면 앱으로 이동합니다. 사용자 id가 없는 오래된 세션은 이번 실행에서만 진행합니다. 재설치·다른 기기 간 단계 동기화는 하지 않습니다.
- 중복 탭은 동기 잠금으로 막고 POST를 자동 재시도하지 않습니다. 저장 실패/응답 유실은 선택을 유지하고 서버 목록을 다시 확인합니다. 루틴 등록 API에 서버 멱등 키가 없으므로 여러 기기의 동시 등록까지 한 건으로 보장하는 계약은 아닙니다.

## 측정

서버의 온보딩 `completed` 정의(목표 ≥ 1개 + 대표 캐릭터)는 변경하지 않습니다. 관리자 온보딩 완료율과 루틴 생성률은 서로 다른 지표입니다.

| 이벤트                   | 발생 시점                                 | 부가 값                                                   |
| ------------------------ | ----------------------------------------- | --------------------------------------------------------- |
| `starter_routine_view`   | 기존 루틴 조회 성공 후 추천 화면을 보여줌 | `recommendation_count`                                    |
| `starter_routine_skip`   | 나중에 선택                               | 없음                                                      |
| `starter_routine_failed` | 명시적 생성 시도 실패                     | 정해진 `template_id`                                      |
| `routine_create`         | 서버가 생성한 id를 응답함                 | `kind=routine`, `source=onboarding`, 정해진 `template_id` |

닉네임·직접 입력한 루틴 제목·관심사 원문은 새 이벤트로 전송하지 않습니다. 기존 GA4 개발 수집 비활성 정책을 따릅니다. 웹 검증은 이벤트 호출 배선을 테스트하며 GA4 수신 검증을 대체하지 않습니다.

배포 버전/가입 코호트별로 가입→온보딩 완료→첫 루틴 생성→가입 24시간 내 첫 루틴 수행 완료를 비교합니다. 첫 발생은 GA4의 사용자별 최초 이벤트로 집계하며 투두(`kind=todo`)는 제외합니다. 추천 노출→생성 전환과 건너뛰기·저장 실패도 함께 확인합니다. 응답 유실 시 생성 이벤트가 누락될 수 있어 서버 루틴 기록과 함께 해석합니다. 리텐션은 동일한 분모·코호트 성숙 기간으로 비교합니다(#1045).

2026-09-06 사용자가 제공한 관리자 화면은 온보딩 61/98(62.2%), D1 5/57(8.8%), D7 1/37(2.7%)입니다. 이는 해당 화면의 스냅샷이며 루틴 생성 전 이탈 원인을 확정하는 근거는 아닙니다.
