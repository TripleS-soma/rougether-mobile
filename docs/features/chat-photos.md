# 집 채팅 사진

입력창 사진 버튼 → 시스템 사진 선택기 → 미리보기 → 보내기 순서다. JPEG/PNG 한 장(10MB 이하)을 보낼 수 있다. 실패한 사진은 같은 메시지 ID와 업로드 ID로 재시도한다. 목록 재조회로 실패한 말풍선을 지우지 않는다.

서버 #532와 spec #155 계약을 사용한다. 사진은 공개 CDN이 아닌 인증 API로 읽고 디스크에 캐시하지 않는다. 배경 진입과 로그아웃 시 표시를 비우며 복귀 시 접근 권한을 다시 확인한다. 계정이나 집이 바뀐 뒤 이전 업로드를 전송하지 않는다. 다른 구성원의 메시지는 신고할 수 있다.

기존 Expo SDK 55 사진 선택기를 사용하며 네이티브 설정과 권한 요청을 추가하지 않는다. 개인정보처리방침 2.4(landing #77)에 선택한 사진의 수집, 현재 집 구성원 공개, 삭제와 AI 미전송을 반영했다. 사진 접근 권한과 재전송 경로는 API 세션·훅·화면 테스트로 검증한다.

발행 전 서버의 인증 업로드/조회/취소를 확인한다. production과 이전 iOS/Android 런타임 모두에 발행하며 네이티브 지문은 기존 설치본과 대조한다. 앱 업데이트 게시 성공과 개별 기기의 업데이트 수신은 별도로 판단한다.

## 크게 보기와 피드에 올리기 (2026-11-11)

말풍선 사진을 누르면 검정 바탕의 전체 화면 보기가 열린다. 왼쪽 위에 뒤로가기와 보낸 사람·보낸 시각이 있다. 종전에는 테마 바탕 위에 사진이 작게 떠 있고 "닫기" 글자만 있었다.

내가 보낸 사진에는 가운데 아래에 [피드에 올리기]가 붙는다. 누르면 그 사진이 붙은 피드 작성 화면(자유게시판)이 열리고, 본문을 쓴 뒤 직접 [올리기]를 눌러야 게시된다. 사진은 메모리에 있던 것을 피드 업로드 API로 다시 올린다 — 채팅 사진을 디스크에 쓰지 않는 원칙은 그대로다. 채팅 사진은 그 집 구성원에게만 보이는 사진이라, 남이 보낸 사진에는 이 버튼을 붙이지 않는다. 피드가 꺼진 빌드에도 없다.

작성 화면에서 뒤로 가면 채팅이 아니라 피드 탭으로 간다(작성 화면의 기존 뒤로 경로).

기기 앨범에 저장하는 기능은 넣지 않았다. 원본 저장에는 파일 쓰기 모듈이 직접 의존성으로 필요하고, 추가하면 네이티브 지문이 바뀐다.

## 여러 장 묶어 보내기 · 자르기 · 공감 (2026-11-13)

위 첫 문단의 "미리보기 → 보내기"와 "한 장"은 이 절로 대체한다. 서버가 이 절의 계약(사진 여러 장·함께 보내는 글·공감·자르기)을 배포한 뒤에 앱을 발행한다 — 옛 서버는 `imageIds`를 모른다.

- 사진 버튼을 누르면 시스템 사진 선택기에서 최대 10장을 고른 순서대로 받는다. 고른 사진은 전체 화면 미리보기가 아니라 입력줄 위 미리보기 줄에 작게 담긴다. 더 누르면 남은 자리만큼만 더 고른다. 서버가 받지 않는 형식·크기(10MB 초과, JPG·PNG 아님)는 담을 때 빼고 안내한다.
- 보내기를 누르면 담긴 사진과 입력칸의 글이 **메시지 하나**로 나간다. 글이 비어 있어도 사진만 나간다. 사진은 한 장씩 차례로 올리고, 중간에 끊기면 다시 보낼 때 이미 올린 사진은 다시 올리지 않는다. 서버가 메시지를 거부하면 올려 둔 사진을 바로 취소한다(미전송 한도 30장을 잡아먹지 않게).
- 담긴 사진을 누르면 자르기 화면이 열린다. 틀을 끌어 옮기고 네 모서리로 크기를 바꾸며, 원본·1:1·4:3·3:4 버튼이 있다. 여기서는 영역(0~1 비율)만 정하고 파일은 건드리지 않는다. 서버가 올릴 때 그 영역만 남긴다. 그래서 화질이 한 번만 깎이고 이미지 편집 네이티브 모듈이 필요 없다. 올라가기 전의 말풍선과 미리보기는 원본을 가려서 자른 모습을 흉내 낸다.
- 받은 사진은 한 장이면 비율을 살려(3:4 ~ 4:3) 크게, 여러 장이면 묶음 격자로 그린다. 한 줄에 최대 3칸이고 3으로 나눠떨어지지 않으면 앞줄을 2칸으로 둔다. 함께 보낸 글은 그 아래 말풍선으로 붙는다. 서버가 옛 앱용으로 채우는 `content`("사진을 보냈어요")는 그리지 않는다.
- 이모티콘은 이번에 넣지 않았다. 서버 계약(`emoticonKey`, 유형 `EMOTICON`)은 들어가 있지만 앱에는 고르는 판도 그림도 없고, 전용 그림이 준비되면 추가한다. 그때까지 이모티콘 메시지를 받으면 서버의 대체 문구("이모티콘을 보냈어요")가 글 말풍선으로 보인다.
- 말풍선을 길게 누르면 메뉴가 **그 말풍선 바로 옆에** 뜬다(카카오톡식, 2026-11-14). 말풍선 아래에 붙이고 아래가 모자라면 위로 올리며, 남의 말풍선은 왼쪽 끝·내 말풍선은 오른쪽 끝을 맞춘다. 위에 공감 여섯 개(하트·좋아요·확인·웃음·놀람·슬픔)가 든 둥근 줄, 아래에 이름은 왼쪽·아이콘은 오른쪽인 목록(복사·공유·신고)이 있다. 공유는 글을 시스템 공유 시트로 넘기며 글이 있는 메시지에만 나온다. 답장·삭제·공지처럼 서버 계약이 필요한 항목은 넣지 않았다. 말풍선 옆에 늘 떠 있던 "신고" 글자는 없앴다. 신고는 남의 메시지에만, 복사는 글이 있는 메시지에만 나온다. 보내는 중이거나 실패한 메시지는 메뉴가 열리지 않는다.
- 공감은 한 사람이 메시지당 하나다. 말풍선 아래 칩에 유형별 사람 수가 보이고, 칩을 눌러 같은 공감을 남기거나 내 공감을 취소한다. 누르면 화면에 먼저 반영하고 서버 응답으로 맞추며 실패하면 되돌린다. 다른 사람의 공감은 소켓 `MESSAGE_REACTIONS`로 받는다(구독 때 `includeReactions`를 보낸다). 놓친 변경은 기록을 다시 받을 때 맞춰진다.

입력줄과 말풍선은 카카오톡에 맞췄다(2026-11-14 제보 "글씨·아이콘이 너무 크다"). 입력줄은 한 줄 알약 모양이다. 알약 안 왼쪽에 작은 둥근 사진 버튼(30), 가운데 글, 오른쪽에 위로 솟는 화살표의 둥근 보내기 버튼(32)이 들어가고, 치수는 카카오톡 입력줄을 재서 옮겼다. 말풍선·입력칸은 `body`, 시각·안 읽은 수·보낸 사람 이름·날짜 구분선은 `caption` 롤을 쓰고 말풍선 여백을 줄였다. 글자 크기 자체는 앱 공용 크기표를 따른다 — 본문 15·가장 작은 글자 11로 줄이는 변경과 설정의 글자 크기 선택은 별도 PR(`feat/font-size-setting`)이고, 그 PR이 머지되기 전에는 채팅 글자도 종전 크기(18·13)로 보인다. 사진을 못 불러온 칸은 문구 대신 다시 불러오기 아이콘을 보인다(묶음의 작은 칸에 문구가 들어가지 않는다).

네이티브 모듈·권한·`app.json`을 건드리지 않았다. 사진 선택기의 여러 장 선택과 새 아이콘(자르기·보내기 화살표·공유)은 이미 들어 있는 패키지의 기능이다.
