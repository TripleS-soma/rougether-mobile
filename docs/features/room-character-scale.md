# 개인 방 캐릭터 크기

꾸미기에서 캐릭터 크기 버튼을 누르면 크기 패널이 열린다. 70~130%, 1% 단위로 조절하고 기본 크기는 100%다. 드래그 중 미리보기하고 손을 떼면 실행 취소 한 단계로 기록한다. 기존 적용/취소 흐름에 포함되며 내 방, 방문, 집 미리보기와 위젯 캡처에도 같은 값이 전달된다.

## 중심과 발 위치

`characterFrameStyle`이 방의 가로 중앙과 바닥 기준점을 고정한다. 이미지의 투명 여백까지 고려하기 위해 `characterArtOffset`이 그림 중심을 정렬하고 발끝의 기존 세로 위치를 유지한다. 원본 이미지와 캐릭터 선택/포즈 순서는 바꾸지 않는다.

`character-art-anchors.json`은 번들 32개 포즈와 공개 CDN 40개 이미지의 첫 프레임에서 alpha > 30인 그림 영역을 측정한 값이다. square contain 기준으로 환산하므로 원본 가로세로 비율과 투명 하단 여백이 모두 반영된다. 파일 자체를 자르거나 수정하지 않는다.

새 서버 포즈를 등록하거나 같은 키의 그림을 바꾸면 아래 명령으로 보정값을 갱신한다. 알려지지 않은 서버 에셋은 프레임 중앙/하단 고정으로 표시되지만 투명 여백 보정은 적용되지 않으므로 출시 전 측정값을 함께 추가한다.

```sh
node scripts/measure-character-anchors.js [characters/new-asset.webp ...]
```

## 저장 및 배포

기존 `PUT /rooms/me/layout`에 `characterScale`을 추가한다. 서버 기본값은 1.00이고 생략/null이면 현재 값이 유지된다. 기존 layout revision 검증과 같은 트랜잭션으로 저장한다. API 응답이 없는 이전 서버에서는 기본 100%로 렌더한다.

서버의 추가 컬럼/API를 먼저 배포한 후 모바일 기능을 배포해야 한다. 패키지나 네이티브 설정 변경은 없다.

## 로컬 확인

`/dev?entry=RoomDecorScreen&viewport=1`에서 캐릭터 크기 버튼을 누른다. 슬라이더 양 끝으로 드래그해 가로 중앙과 발끝이 유지되는지, 기본 크기 복원, 실행 취소, 적용, 변경 후 나가기 확인을 검사한다. 이는 픽스처 UI 검증이며 운영 저장 검증을 대신하지 않는다.

## 검증 결과 (2026-11-11)

- 앱 전체 455개 테스트 묶음, 3,827개 테스트 통과(기존 TODO 4개). 이후 추가한 여우 에셋 4개를 포함한 보정값/아바타/슬라이더 테스트 84개도 통과.
- 타입 검사, 린트, 포맷 검사 통과.
- 390px 웹 화면에서 실제 드래그로 70/100/130% 확인. 캔버스 기준 발끝 Y는 331.2081/331.2065/331.2050px로 최대 차이 0.0032px였고, 그림 중심은 프레임 중심에서 0.01px 이내였다.
- 드래그 한 번 실행 취소와 100% 초기화 확인. 네이티브 기기 및 운영 저장 검증은 배포 후 별도 확인 대상이다.
