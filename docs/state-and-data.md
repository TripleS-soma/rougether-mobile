# 상태 & 데이터

> 도구 중립: 특정 라이브러리를 못 박지 않는다. 아래 **원칙·패턴**을 따르고,
> 실제 라이브러리 선택은 "열린 결정"에서 합의한 뒤 이 문서에 확정 표기한다.

## 상태 분리 원칙

상태를 종류로 나눠 다루는 곳을 고정한다.

| 종류                   | 예                              | 사는 곳                                        |
| ---------------------- | ------------------------------- | ---------------------------------------------- |
| **서버 상태**          | 루틴 목록, 방 스냅샷, 지갑 잔액 | API에서 받아온 캐시. 화면이 아니라 데이터 계층 |
| **클라이언트/UI 상태** | 모달 열림, 폼 입력, 탭 선택     | 컴포넌트 `useState` / 최소한의 전역            |
| **영속 상태**          | 인증 토큰, 온보딩 완료 플래그   | secure/async storage                           |

서버 상태를 컴포넌트 `useState`로 들고 다니지 않는다 (동기화·로딩·에러가 흩어진다).

## spec API 연동

API **계약**은 spec이 진실 소스다. 여기서 엔드포인트/필드를 재정의하지 않는다.

- 공통 규약: [spec api.md](https://github.com/TripleS-soma/rougether-spec/blob/main/api.md)
- 도메인별: `spec/domains/<도메인>/api.md`

계약에서 **프론트가 반드시 지켜야 하는 것**(상세는 spec 링크 참조, 값 복붙 금지):

- **base path** `/api/v1` — API 클라이언트 한 곳에서 prefix.
- **에셋은 key로** 주고받음 (`asset_key`/`cover_image_key`/`storage_key`). 프론트가 **CDN base URL과 조합**해 실제 URL 생성 → `assetUrl(key)` 헬퍼 한 곳에.
- **시각은 ISO-8601 + offset, 타임존 KST(Asia/Seoul)** — 당일/자정 판정은 KST 기준. 날짜 유틸을 KST로 고정 (디바이스 로컬타임에 의존 금지).
- **목록 응답은 `items` 배열**로 래핑 — 클라이언트 타입도 `{ items: T[] }`.
- **인증: 소셜 로그인(카카오·구글·애플) + JWT** — 토큰은 secure storage, 요청에 Authorization 주입. `me` path = 인증 사용자.
- **에러 바디 공통 포맷** — 전역 에러 핸들러/인터셉터에서 일괄 처리, 화면은 표준 에러 UI만.

## 데이터 계층 패턴 (도구 무관)

- **단일 API 클라이언트** (`src/lib/api/` 가칭): base URL/`/api/v1` prefix, 토큰 주입, 에러 정규화, asset-key 조합을 한 곳에 둔다.
- **도메인별 fetch 함수 + 타입**: spec 계약과 1:1. 응답 타입은 spec 필드명을 그대로.
- **화면은 훅으로 소비**: `useRoutines()` 같은 훅이 서버 상태(로딩/에러/데이터)를 캡슐화. 화면은 표현만.
- **로딩/에러/빈 상태 3종**을 항상 처리 — 공통 컴포넌트로 표준화.
- **낙관적 업데이트**(완료 체크 등)는 서버상태 도구의 패턴을 따른다.

## 열린 결정 (정해지면 여기 확정 표기)

- **서버 상태 도구**: TanStack Query vs RTK Query vs SWR vs 수제 훅.
- **클라이언트 전역 상태**: Context vs Zustand vs Jotai (필요해질 때).
- **영속 저장소**: expo-secure-store(토큰) + async-storage(플래그) 조합 확정.
- **타입 출처**: spec에서 타입 생성 자동화 vs 수기 작성.
- **CDN base URL** 환경변수 키와 주입 방식.
