# 웹 구글 로그인이 누르자마자 실패 — 구글 버튼이 iframe으로 바뀌어 막힌 "숨은 버튼 클릭"

- 2026-10-13 / member(로그인) / 관련: #1532 · #1533 (원 구현 #1225)
- 키워드: Google Identity Services, OAuth 2.0 / OpenID Connect 암묵 흐름, state·nonce, cross-origin iframe, 리다이렉트 로그인, 테스트 스텁 드리프트

## 배경

웹앱(app.rougether.com)의 구글 로그인은 GIS(Google Identity Services)로 id token을 받아 서버 `/auth/google`에 넘긴다(네이티브와 같은 계약). GIS가 id token을 주는 경로는 One Tap과 **공식 버튼**뿐이라, 우리 디자인 버튼을 유지하려고 공식 버튼을 화면 밖에 숨겨 그려 두고 사용자가 우리 버튼을 누르면 그 안의 `div[role="button"]`을 JS로 클릭하는 방식이었다.

## 문제 (증상)

"구글 로그인이 안 된다." PC 크롬에서 'Google로 시작하기'를 누르면 구글 창 없이 즉시 "구글 로그인에 실패했어요". 같은 날 앱 OTA·서버 배포가 있어 그쪽을 먼저 의심하기 쉬웠다.

## 원인 분석 (가설 → 검증 과정)

1. **서버**: 운영 `/auth/google`에 가짜 토큰을 보내 정상 401(`AUTH_OAUTH_GOOGLE_TOKEN_INVALID`)과 웹 CORS preflight 200을 확인 — 서버 무관.
2. **당일 배포**: 로그인 경로를 건드린 변경은 웹 셸 색 토큰화 하나뿐(출력 동일) — 무관.
3. **운영 페이지 재현**: 버튼을 누르면 구글·서버로 가는 요청이 **하나도 없고** Sentry 보고만 나감 → 앱 코드 안에서, 구글 창을 열기 전에 실패.
4. 페이지 상태를 직접 조사: GIS 스크립트는 로드돼 있고 숨은 영역도 있는데, 그 안에 **`div[role=button]`이 없고 iframe만** 있었다. GIS가 버튼을 구글 도메인 iframe 안에 그리도록 바뀐 것 — 우리 페이지는 교차 출처 iframe 안의 버튼을 찾지도 누르지도 못한다. 코드는 그대로 `google sign-in button not rendered`를 던졌다.
5. 우리 코드는 원 구현 이후 바뀌지 않았다. 단위 테스트 스텁이 **예전 GIS처럼 `div[role=button]`을 그리고 있어** 외부 변화를 잡을 수 없었다.

## 해결

1. 처음엔 공식 버튼을 그 자리에 **직접 노출**했다(사용자 제스처가 iframe 안에서 일어나니 정석). 로컬에서 버튼 → 구글 창까지 동작했지만, 공식 버튼은 최대 400×40·고정 모서리라 카카오 버튼과 크기가 맞지 않았다.
2. 사용자 결정으로 **카카오 웹처럼 페이지 리다이렉트**로 교체: `accounts.google.com/o/oauth2/v2/auth?response_type=id_token&prompt=select_account&state&nonce` → `/login#id_token=…` 복귀 → 로그인 라우트가 복귀를 감지해 `/auth/google`까지 끝낸다.
   - `state`(CSRF)와 토큰 본문의 `nonce`(재사용 방지)를 대조, 서명 검증은 서버가 그대로.
   - 토큰이 주소창·히스토리에 남지 않게 프래그먼트를 즉시 제거.
   - 서버 변경 없음(aud = 같은 웹 클라이언트 ID). 버튼 디자인도 그대로.
3. Google Cloud Console 웹 클라이언트에 승인된 리디렉션 URI(운영·로컬)를 등록 — 등록 전엔 `redirect_uri_mismatch`로 흐름이 맞게 도는 것부터 확인했다.

## 결과 (수치)

- 운영에서 버튼 → 계정 선택 → 복귀 → 로그인 완료 확인(로컬·운영 둘 다, 실제 계정).
- 회귀 테스트: 라우트의 구글 복귀 2개는 이전 코드에서 실패, 순수 조각 8개·브라우저 배선 4개 추가. 전체 399 스위트 통과.
- 공식 버튼안의 One Tap 대체 경로 테스트가 구현 버그(콜백이 대기 슬롯을 먼저 비워 결과가 버려짐)를 잡았다 — 최종안에선 빠졌지만 테스트를 먼저 쓴 덕에 잡혔다.

## 배운 점 / 재발 방지

- **서드파티 위젯을 DOM으로 조작하는 우회는 그쪽 렌더링 하나에 무너진다.** 공식 위젯을 그대로 쓰거나, 표준 프로토콜(OAuth 리다이렉트)로 의존을 표면적으로 줄이는 쪽이 오래 간다.
- **테스트 스텁은 외부 동작의 '그때 사진'이다.** 외부 라이브러리 흉내가 바뀌면 테스트는 계속 초록인 채 운영만 깨진다 — 스텁에 "실제로 무엇을 그리는지"를 주석으로 남기고, 현재 동작으로 갱신했다.
- 같은 날 배포가 있어도 "요청이 어디까지 나갔나"(네트워크)부터 보면 서버·배포·클라이언트를 몇 분 안에 가를 수 있다.
