# 선택 툴바가 편집 대상을 가리던 문제 — 리렌더 없이 드래그에 반응하는 툴바

- 2026-07-30 / room(방 꾸미기 편집기) / 이슈 #608, PR #609 (선행: #327·#333, 후속: #1064)
- 키워드: 제스처와 렌더 분리, UI 스레드(Reanimated worklet·SharedValue), RNGH 팬 제스처 수명, 선택 툴바 배치(dodge), 유령 터치 차단, 제스처 테스트(fireGestureHandler)

## 배경

방 꾸미기는 작은 캔버스 편집기다. 가구를 탭하면 선택 링과 함께 **선택 툴바**(회전 2개·반전·앞으로·뒤로·빼기, 6버튼)가
뜨고, 선택된 가구는 손가락으로 끌어 옮긴다(#327·#333). 이동은 RNGH 팬 제스처 + Reanimated SharedValue로
UI 스레드에서만 움직이고, 손을 떼는 순간에만 JS로 좌표를 커밋한다.

이 구조에는 #327에서 이미 얻은 규칙이 하나 있었다. 웹 스모크 중 드래그가 중간에 끊기는 버그를 잡다가 확인한 것으로,
**드래그 중에 React 상태를 바꾸면 리렌더가 제스처 객체를 다시 만들고, 그 과정에서 진행 중인 팬이 취소된다.**
그래서 z 승격(끌고 있는 가구를 맨 앞으로)도 드래그 시작이 아니라 드롭 커밋으로 옮겨 두었고, `draggable-furniture.tsx`
주석에 "드래그 중에는 React 상태를 건드리지 않는다"고 박아 두었다.

## 문제 (증상)

선택 툴바가 캔버스 **상단 중앙에 고정**(`top: Spacing.two + 48`, zIndex 10001)돼 있었다. 벽 쪽, 즉 캔버스 상반부에
가구를 두면 툴바가 정확히 그 가구 위를 덮었다.

- 드래그하는 동안 가구가 툴바 밑으로 들어가 어디에 놓는지 보이지 않는다.
- 놓은 뒤에도 벽지와 어울리는지 최종 모습을 확인할 수 없다.
- 회전·반전은 결과를 보면서 연타하는 버튼인데, 결과가 가려진다.

## 원인 분석 (가설 → 검증 과정)

원인 자체(고정 위치)는 명확했다. 어려운 건 해법 쪽이었다.

1. **대안 비교.** 반투명 툴바는 가림과 터치 겹침을 둘 다 남겨서 기각했다. 툴바를 캔버스 밖에 고정하는 안은 아래
   카탈로그 공간을 잠식하고 시선 이동 거리가 길어져서 기각했다. 남은 안은 두 가지를 합친 것이다.
   - **위치 회피**: 표시 시점에 선택 가구가 상반부면 툴바를 아래로 보낸다.
   - **드래그 중 숨김**: 끄는 동안 툴바를 치운다.
2. **회피 시점.** 드래그 중에도 실시간으로 위아래를 바꾸면 툴바가 경계에서 튄다. 선택·드롭 시점에만 위치를
   정하기로 했다. 회전·반전 연타 중에는 가구 y가 바뀌지 않으므로 툴바도 흔들리지 않는다.
3. **"드래그 중 숨김"이 막힌 지점.** 가장 단순한 구현은 `onDragStart`에서 `setDragging(true)`를 부르고 툴바를
   조건부로 그리는 것이다. 하지만 이것이 바로 #327 규칙이 금지한 경로다. 상태가 바뀌면 화면이 리렌더되고,
   리렌더는 활성 팬을 취소한다. 툴바를 숨기는 순간 드래그가 끊기는 셈이다.
   필요한 것은 "드래그 중"이라는 신호를 **React 렌더 트리를 거치지 않고** 툴바에 전달하는 방법이었다.

## 해결

드래그 상태를 React 상태가 아니라 **UI 스레드 SharedValue 하나**로만 다뤘다.

- 부모(`room-decor-screen.tsx`)가 `dragActive` SharedValue를 소유하고, 가구 컴포넌트에 `dragActiveSV` prop으로 내려준다.
  prop 문서에 "React 상태로 올리면 리렌더가 활성 팬을 취소하므로 SV 전용"이라고 적었다.
- 팬 제스처의 워클릿이 UI 스레드에서 직접 쓴다. `onStart`에서 `true`, `onFinalize`에서 `false`로 바꾼다.
  `onEnd`가 아니라 `onFinalize`에서 내리는 이유는, 취소·중단 경로에서도 항상 실행돼 툴바가 숨은 채 남지 않기 때문이다.
- 툴바는 `Animated.View`로 바꾸고 `useAnimatedStyle`로만 구독한다. 이 스타일은 다음 두 가지를 바꾼다.
  - opacity를 120ms `withTiming`으로 0까지 내린다.
  - `pointerEvents`를 `'none'`으로 바꾼다. 숨은 툴바의 빼기 버튼을 두 번째 손가락이 누르는 유령 터치를 막기 위해서다.
    이 저장소에서 `pointerEvents`를 애니메이션 스타일 반환값에 넣은 첫 사례다.

  결과적으로 드래그 동안 JS 쪽 리렌더는 0회이고, 팬은 끊기지 않는다.

- jest 환경의 `useSharedValue`는 렌더마다 새 객체를 돌려주므로, `useRef(useSharedValue(false)).current`로
  앵커했다. 성능 리팩터 #539에서 정한 계약을 따른 것이다.
- 위치 회피는 React 쪽에서 처리한다. 선택 가구의 정규화 y가 `0.5` 미만이면 `toolbarBottom`(`bottom: Spacing.two`),
  아니면 기존 `toolbarTop`을 쓴다. 드롭 커밋은 원래 리렌더를 일으키므로, 위치 재계산이 드롭 시점에 자연스럽게 따라온다.
  찾지 못하면 `?? 1`로 상단 기본값에 떨어진다.
- 워클릿 안에서만 SharedValue를 쓰도록 지켰다. 직전 크래시 핫픽스 #600(워클릿이 일반 JS 함수를 호출해 안드로이드 앱이
  종료되던 문제)과 같은 계열의 실수를 다시 만들지 않기 위해서다.

## 결과 (수치)

- 이슈 등록(06:12Z)부터 PR 머지(06:24Z)까지 같은 날 처리했다.
- 테스트 2건을 추가했고, PR 시점 전체 659개가 통과했다. 테스트는 RNGH `fireGestureHandler`로 실제 팬 상태 전이를 흘려 검증한다.
  - y=0.3 가구를 선택하면 툴바에 `bottom`이 있고 `top`은 없다.
  - y=0.7 가구는 처음에 `top` 자리에 있다. 320px 캔버스에서 중심 224px을 위로 160px 끌어 64px(y=0.2)에 놓으면
    `bottom`으로 옮겨 간다.
- 웹 스모크 결과: 벽 선반 선택 시 `bottom: 8px`, 침대 선택 시 `top: 56px`였고, 드래그·드롭 후 정상 복귀를 확인했다.
- 드래그 중 fade 자체는 웹 계측 한계로 자동 검증하지 못했다. 실기기 육안 확인 항목으로 남겼다.
- 프레임레이트는 측정하지 않았다. "드래그 중 리렌더 0회"는 구조상 보장되는 성질이고, 60fps 유지는 측정값이 아니라 기대다.

## 배운 점 / 재발 방지

- **제스처 수명과 렌더 수명은 분리해야 한다.** 캔버스 편집기에서 "드래그 중"에 반응해야 하는 UI(툴바, 가이드, 스냅 표시)는
  React 상태가 아니라 UI 스레드 값으로 구독하게 만든다. 상태로 올리는 순간 제스처가 끊긴다.
- 숨기는 UI는 보이지 않을 뿐 아니라 **터치도 받지 않아야** 한다. opacity만 내리면 숨은 버튼이 여전히 눌린다.
- "드래그 해제"는 성공 경로(`onEnd`)가 아니라 **모든 종료 경로**(`onFinalize`)에 둔다.
- 선택 툴바 위치는 실시간 추적보다 **확정 시점(선택·드롭)에만 결정**하는 편이 연타 조작에 안정적이다.
- 규칙은 주석과 prop 문서에 남긴다. #327에서 얻은 "드래그 중 리렌더 금지" 주석이 있었기에, 이번엔 잘못된 구현을
  먼저 시도해 보지 않고 바로 SharedValue 설계로 갔다.
