# 멈춰 둔 캐릭터가 Android에서만 다시 움직인 문제 — 한 번의 stop()과 다시 보일 때마다 재생하는 드로어블

- 2026-11-11 / design(캐릭터) / PR #1703(정지 그림 전환) · #1708(웹) · 이 PR(Android)
- 키워드: expo-image `autoplay`, Glide, 애니메이션 WebP, `Drawable.setVisible`, 플랫폼별 동작 차이, 바이트코드로 라이브러리 동작 확인

## 배경

캐릭터의 움직이는 webp가 "떠다니는 느낌"이라는 피드백으로, 그림을 첫 장면에 멈추고 그 위에 숨쉬기·탭 반응만 얹기로 했다(#1703). 구현은 expo-image의 `autoplay={false}` 한 줄이었다. 웹은 브라우저가 이 속성을 무시해서 앱에 든 정지 그림으로 바꿨다(#1708).

## 문제 (증상)

사용자 제보: Android 앱에서는 캐릭터가 여전히 움직인다.

## 원인 분석 (가설 → 검증 과정)

1. **재현**: 에뮬레이터의 릴리스 APK에서 방 화면을 0.45초 간격으로 여섯 장 찍어 캐릭터 부분만 이어 붙였다. 머리 기울기와 몸 위치가 장마다 달랐다 — 숨쉬기(세로 2%)로는 설명되지 않는 움직임이다. 재생 중이 맞다.
2. **expo-image Android 소스**: `autoplay`가 꺼져 있으면 그림이 준비된 순간 `resource.stop()`을 **한 번** 부른다(`ExpoImageViewWrapper.kt`). 속성 자체는 Android에서도 처리한다.
3. **그러면 누가 다시 트나**: 움직이는 webp는 Glide 기본 디코더가 아니라 penfeizhou `FrameAnimationDrawable`이 그린다(expo-image의 `build.gradle`). Gradle 캐시의 aar를 풀어 `javap`로 `setVisible`을 보니 자체 `autoPlay` 필드를 읽고, 보이게 될 때 재생 중이 아니면 `start()`를 부른다. 이 필드는 expo-image의 `autoplay`와 무관하게 기본값이 켜져 있다.

즉 expo-image가 멈춘 그림을, 뷰가 다시 보이게 되는 순간(탭 전환·앱이 앞으로 옴·첫 부착) 드로어블이 스스로 다시 재생했다. iOS는 다른 디코더라 이 경로가 없다.

## 해결

재생을 끈 상태에서는 **iOS가 아니면** 서버의 움직이는 파일을 쓰지 않고 앱에 든 정지 포즈를 그린다. 웹용으로 만들어 둔 분기(`preferBundledStill`)의 조건을 `web`에서 `iOS 아님`으로 넓혔다. 네이티브 코드를 건드리지 않아 OTA로 나간다.

버린 대안: 뷰가 보일 때마다 JS에서 `stopAnimating()`을 다시 부르는 방법 — 보이는 시점을 JS가 다 알 수 없고(앱 복귀, 페이저), 멈추기 전 한두 프레임이 새어 나온다.

## 결과 (수치)

- 같은 에뮬레이터 세션, 릴리스 APK, 0.45초 간격 여섯 장: 수정 전 장마다 자세가 다름 → 수정 후 여섯 장 모두 같은 자세(숨쉬기의 세로 변화만).
- 테스트 1건 추가(Android에서는 CDN 애니메이션 뷰를 만들지 않음).

## 배운 점 / 재발 방지

- 라이브러리의 "끄기" 속성은 **언제 한 번 적용되는지**까지 봐야 한다. "준비됐을 때 한 번 stop"은 그 뒤 누가 다시 start하면 무력하다.
- 플랫폼 세 곳(iOS·Android·웹)에 같은 속성을 줬다면 세 곳을 각각 확인한다. 웹에서 한 번 속았는데 Android를 다시 확인하지 않았다.
- 소스가 없는 의존성도 aar → `classes.jar` → `javap -c`로 메서드 하나의 분기는 읽을 수 있다.
