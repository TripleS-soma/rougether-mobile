# 초대 링크를 누르면 방 화면만 뜨는 문제 — 웜 스타트에서 앱 셸이 둘이 되던 딥링크 리다이렉트

- 2026-10-12 / house(초대) / 관련: #624·#896(딥링크 핸드오프), 이번 수정 PR
- 키워드: Expo Router 딥링크, 내비게이션 스택, 웜/콜드 스타트, 이펙트 순서, 에뮬레이터 logcat 계측

## 배경

집 초대 링크는 랜딩(`rougether.com/join.html?code=…`)이 `rougether://join?code=…`로 앱을 연다. 앱의 `/join` 라우트가 코드를 대기 저장소에 맡기고 루트로 돌아가면, 앱 셸이 구독해 집 탐색의 코드 미리보기·신청으로 잇는다. 코드는 "처리 완료"를 알려올 때까지 보관한다(#896).

## 문제 (증상)

"초대 링크를 누르면 집 신청 화면이 아니라 방 화면으로 가고, 신청도 안 된다." 웹과 앱을 새로 켤 때(콜드 스타트)는 정상이었다.

## 원인 분석 (가설 → 검증 과정)

1. 랜딩이 넘기는 주소 확인 — `rougether://join?code=` 정상.
2. 웹 재현 — 정상(집 탐색 + 코드 미리보기).
3. 에뮬레이터 개발 빌드에서 `adb shell am start -d rougether://join?code=…`:
   - 앱이 꺼진 상태 → 정상.
   - **앱이 방 화면에 떠 있는 상태 → 방 화면**(재현). 2초 시점엔 화면이 비었다가 방이 뜸.
4. 셸 마운트·화면 전환·코드 수신에 임시 로그를 심어 순서를 봤다:
   `join route effect → shell got code → screen houseSearch → shell mount → screen myRoom`.
   **코드는 기존 셸이 받아 집 탐색으로 갔지만, 곧이어 셸이 하나 더 마운트됐다.**

**원인**: 웜 스타트에서 `/join`은 기존 셸 위에 쌓인다. 그 라우트가 `<Redirect href="/">`로 루트를 **새로** 열어 셸이 둘이 됐다. 가려진 옛 셸의 집 탐색이 코드를 쓰고 "처리 완료"로 지웠고, 사용자에겐 코드를 못 받은 새 셸의 방 화면만 보였다. 콜드 스타트는 셸이 하나뿐이라 문제가 없었다.

## 해결

딥링크 라우트 공용 훅 `useDeepLinkHandoff`: 이펙트에서 코드를 맡긴 뒤 **뒤 화면이 있으면 `router.back()`으로 기존 셸로 돌아가고**, 없을 때(콜드 스타트)만 `replace('/')`. 친구 초대(`/invite`)도 같은 구조라 함께.

## 결과 (수치)

- 같은 에뮬레이터에서 방 화면 출발 웜 딥링크: 집 탐색 + 코드 프리필 + 미리보기, **추가 셸 마운트 0회**(수정 전 1회).
- 회귀 테스트: 웜이면 `handoff → back`, 콜드면 `handoff → replace('/')`. 항상 교체로 되돌리면 3개 실패.

## 배운 점 / 재발 방지

- `Redirect`는 "그 화면으로 가기"가 아니라 "그 경로를 새로 열기"다. 기존 인스턴스로 돌아가야 하는 핸드오프 라우트는 스택을 되감아야 한다.
- 콜드 스타트·웹만 확인하면 놓친다 — 딥링크는 **앱이 떠 있는 상태**를 별도로 재현해야 한다(`adb am start -d`가 실행 중인 인스턴스로 전달).
- "처리하면 지우는" 보관 방식은 소비자가 둘이면 엉뚱한 쪽이 소비한다 — 소비자가 하나라는 전제를 구조로 지킬 것.
