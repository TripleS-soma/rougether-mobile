# 포트폴리오 기록

Rougether는 개발자 개인 포트폴리오에 싣는 프로젝트다. 이 폴더는 **작업 중 실제로 부딪힌 기술적 챌린지와 트러블슈팅**을 나중에 포트폴리오·면접 답변으로 옮길 수 있게 남기는 곳이다. 코드 리뷰용 문서가 아니라 "무엇이 어려웠고, 어떻게 원인을 좁혔고, 무엇을 배웠나"의 기록이다.

## 언제 쓰나

Claude(또는 작업자)가 대화·작업 중 아래에 해당한다고 **스스로 판단하면** 사용자에게 묻지 않고 작성한다.

- 원인이 바로 보이지 않아 가설을 세우고 검증해야 했던 버그·빌드 실패·배포 사고
- 플랫폼·라이브러리 제약(Expo/RN, iOS/Android, EAS, 웹)을 우회하거나 설계로 풀어야 했던 문제
- 규모가 있거나 위험한 변경을 안전하게 나눈 설계 판단(대규모 마이그레이션, 병렬 작업 분할 등)
- 운영 중인 앱에서 사용자 영향을 막기 위해 절차·인프라를 바꾼 일

쓰지 않는 것: 단순 문구 수정, 설명만으로 끝나는 질문, 원인이 즉시 명확했던 오타·설정 실수.

## 형식

- 사례 하나 = 파일 하나: `YYYY-MM-DD-<짧은-영문-슬러그>.md`
- 같은 사례에 후속이 생기면 새 파일이 아니라 그 파일에 `## 후속` 절을 추가한다.
- 본문은 아래 틀을 따른다. 수치(빌드 번호, 지문 해시 앞 8자리, 폭 px, 키 수, 테스트 수)는 **실측값만** 적는다. 추측은 추측이라고 쓴다.

```markdown
# <한 줄 제목>

- 날짜 / 영역(도메인) / 관련 이슈·PR
- 키워드: <면접에서 꺼낼 기술 키워드 3~6개>

## 배경

## 문제 (증상)

## 원인 분석 (가설 → 검증 과정)

## 해결

## 결과 (수치)

## 배운 점 / 재발 방지
```

- 작성 후 아래 목록에 한 줄 추가한다(최신이 위).
- 사용자 계정·토큰·개인 이메일 등 민감 정보는 적지 않는다.
