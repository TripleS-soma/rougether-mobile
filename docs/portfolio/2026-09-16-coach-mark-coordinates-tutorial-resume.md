# 튜토리얼 코치마크가 엉뚱한 곳을 짚고, 앱을 껐다 켜면 튜토리얼이 사라지는 문제

- 2026-09-16 / member·design(온보딩 튜토리얼) / #1397, 후속 PR
- 키워드: 좌표계 변환(measureInWindow), onLayout의 한계, 포털·프레임 오프셋, 반응형 웹 레이아웃, 상태 영속화

## 배경

신규 회원은 온보딩 직후 4단계 미션(루틴 완료 → 첫 뽑기 → 가구 배치 → 친구 초대)을 코치마크로 안내받는다. 코치마크는 화면 전체를 어둡게 덮고 대상 버튼 자리만 뚫어 강조 테두리를 그린다. 대상은 `<CoachTarget>`이 `onLayout`에서 `measureInWindow`로 좌표를 재 전역 저장소에 등록하고, 오버레이가 그 좌표를 읽는다.

## 문제 (증상)

1. 데스크톱 웹(2단 레이아웃)에서 강조 테두리가 선물 버튼이 아니라 오른쪽 빈 곳에 뜨고, 안내 카드가 화면 폭 전체로 늘어남.
2. 이어서 iOS·Android에서도 위치가 맞지 않는다는 보고.
3. 튜토리얼 도중 앱을 껐다 켜면 튜토리얼이 사라지고 다시 나오지 않음.

## 원인 분석 (가설 → 검증 과정)

**위치(웹)**: Playwright로 1600px 창에서 실측 — 선물 버튼 창 기준 x=616, 가운데 앱 프레임 시작 x=200. 대상은 **창 기준** 좌표로 등록되는데 오버레이는 **프레임 안**에 그려진다. 두 좌표계의 원점 차이(프레임 여백 200px)만큼 구멍이 오른쪽으로 밀렸다. 모바일·좁은 웹은 원점이 (0,0)이라 가려져 있던 버그다.

**위치(네이티브)**: 좌표를 `onLayout`에서 한 번만 잰다. `onLayout`은 요소의 크기나 부모 안에서의 위치가 바뀔 때만 불리고, 스크롤·탭 페이저 이동(부모 transform)·배너 등장처럼 **창 기준 위치만 바뀌는 경우엔 불리지 않는다** → 좌표가 낡는다. 셸 원점이 (0,0)이 아닐 때 밀리는 문제도 웹과 같은 뿌리.

**튜토리얼 소실**: 미션 진행 단계가 React 상태(메모리)에만 있었고, 체인 시작 조건 `justOnboarded`도 메모리 값이었다. 재시작하면 둘 다 초기화돼 체인이 시작되지 않고, 완료·건너뛰기 플래그도 없어 영구히 사라진다. 사용자는 "다시 보기에서만 그런가, 첫 유저도 그런가"를 물었는데, 코드상 **두 경로 모두 같은 상태를 쓰므로 첫 유입도 동일**하다고 확인했다.

## 해결

- **좌표계 통일**: 오버레이가 자기 루트의 창 원점을 `measureInWindow`로 재서 대상 좌표에서 뺀다(`toOverlayRect`).
- **재측정**: 대상이 재측정 함수를 저장소에 등록하고, 오버레이가 떠 있는 동안에만 250ms마다 오버레이 원점과 모든 대상을 다시 잰다. 1px 미만 변화는 무시해 재렌더 폭주를 막는다.
- **말풍선 배치**: 넓은 프레임에선 최대 420px로 줄여 구멍 가운데에 두고 프레임 안으로 클램프. 폰 폭은 종전과 동일.
- **문구**: 2단 레이아웃에선 버튼이 방 아래라 "오른쪽의 선물 버튼"을 방향 없는 표현으로.
- **진행 영속화**: 같은 계정 키에 `progress:<단계>`를 저장하고, 마운트 시 진행 기록이 있으면 그 단계부터 재개(시작 이벤트는 중복 계측하지 않음). 종료 플래그와 같은 키라 상태가 하나만 남는다.

## 결과 (수치)

- 실측 좌표(버튼 616, 프레임 200)를 단위 테스트로 고정, 말풍선 배치·재측정 타이머 수명·진행 재개·범위 밖 기록 무시 테스트 추가.
- 관련 스위트(코치마크·미션·셸·방·집) 355 tests 통과.

## 배운 점 / 재발 방지

- 측정 API가 주는 좌표의 **기준 원점**과 그리는 쪽의 원점을 항상 같이 적는다. 원점이 (0,0)인 환경에서만 테스트하면 이런 버그는 영원히 숨는다 — 반응형 웹이 그걸 드러냈다.
- `onLayout`은 "창에서의 위치"가 바뀐 걸 알려주지 않는다. 오버레이처럼 전역 좌표가 필요한 UI는 표시 중 주기적 재측정(또는 스크롤·전환 이벤트 구독)이 필요하다.
- 여러 세션에 걸치는 사용자 흐름(튜토리얼·온보딩)은 "앱을 껐다 켜면?"을 첫 설계 질문으로 둔다. 메모리 상태만으로 시작 조건을 정하면 재시작에서 조용히 사라진다.
