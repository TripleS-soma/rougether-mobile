# 이모티콘 즉시 전송과 남은 사진 초안의 오발송 방어

- 날짜: 2026-11-15 / 집 채팅 / 이슈 #1782
- 키워드: React 배칭, ref, 입력 상태, 더블 탭, 사용자 의도

## 배경

습관 형성을 돕는 소셜 루틴 앱의 집 채팅에서 글과 이모티콘을 함께 보내면 선택 패널을 닫고, 이모티콘만 보내면 유지하도록 바꿨다. 같은 이모티콘을 빠르게 두 번 누르면 보내기 버튼 없이 전송하는 동작도 추가했다.

## 문제 (증상)

기존 중복 방어는 전송 후 선택 패널을 열어두는 상태에도 의존했다. 패널을 닫으면 남은 사진 초안 때문에 보내기 버튼이 다시 활성화될 수 있었다. 또한 첫 선택과 두 번째 탭 사이에 React 렌더가 완료됐다고 가정할 수 없었다.

## 원인 분석 (가설 → 검증 과정)

첫 선택과 다음 탭을 하나의 `act` 안에서 호출하는 테스트로 렌더 전 연속 입력을 검사했다. 선택한 key와 마지막 탭 시각은 ref로 즉시 갱신해야 두 번째 콜백에서 사용할 수 있었다. 전송 후 사진은 보존하되, 새 사용자 조작 전까지 사진 보내기를 보류해 같은 렌더와 다음 렌더의 연속 전송을 나눠 방어했다.

리뷰에서는 키보드가 유지된 입력란에 `onFocus`가 다시 발생하지 않는 경계를 확인했다. 사진 보내기를 재개하는 테스트를 강제 focus 대신 `pressIn`으로 바꾸고 이미 포커스된 입력란의 명시적인 탭도 처리했다.

## 해결

동일 key, 현재 선택과 300ms 이내 연속 탭을 확인한다. 더블 탭과 보내기 버튼은 같은 전송 함수를 사용한다. 전송, 취소와 패널 전환에서 탭 기록을 초기화한다. 글이 있으면 패널을 닫고 없으면 유지하며, 키보드를 강제로 닫거나 열지 않는다. 남은 사진은 입력이나 첨부를 다시 조작할 때 전송 가능 상태로 돌린다.

## 결과 (수치)

관련 3개 테스트 모음의 47개 테스트와 전체 475개 모음의 4,049개 테스트가 통과했다. 기존 todo는 4개다. 브라우저에서 같은 이모티콘 더블 클릭으로 글과 그림이 한 번 전송되고 패널이 닫히는 동작을 확인했다. 실제 기기의 키보드와 연속 터치는 별도 확인 범위다.

## 배운 점 / 재발 방지

선택 UI의 표시 상태를 바꾸면 다른 첨부의 전송 가능 조건도 다시 확인한다. 짧은 연속 입력은 렌더가 완료되기 전과 후를 각각 검사하고, 기존 포커스를 유지하는 흐름에서는 focus와 명시적인 탭을 구분한다.
