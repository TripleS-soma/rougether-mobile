# 안드로이드에서만 뽑기 버튼 아래가 잘리는 문제 — Yoga의 flex 1이 만든 높이 0 기준

- 2026-10-10 / shop-gacha / PR #1493
- 키워드: React Native 레이아웃(Yoga), flex 단축 속성(flexBasis 0), 플랫폼별 레이아웃 차이, Android 에뮬레이터 실기 재현, onLayout 계측

## 배경

출시된 앱(1.5.4)의 뽑기 화면은 위쪽 스크롤 영역(그림·설명)과 아래 고정 영역(`1회 뽑기 / 5+1회 뽑기` 두 버튼)으로 나뉜다. 두 버튼의 폭 비율(1 : 1.5)은 튜토리얼 코치마크 대상 래퍼(`CoachTarget`)가 `flex`로 나눈다.

## 문제 (증상)

갤럭시 S25 기본형 사용자 제보 — 버튼 아래쪽(가격 줄)이 화면 밖으로 잘렸다. 웹(같은 폭 384)과 iOS에서는 멀쩡했고, 같은 폰의 꾸미기 화면 "적용하기" 버튼은 정상이었다. 사용자는 제스처 내비게이션이라 내비게이션 바가 덮은 것도 아니었다.

## 원인 분석 (가설 → 검증 과정)

1. **하단 인셋 누락 가설** — 코드상 `paddingBottom: max(insets.bottom, 12)`를 이미 더하고, 화면이 Android `Modal` 안도 아니었다. 사용자 답(제스처 내비·적용하기 정상)으로 배제.
2. **컨테이너가 화면보다 크다는 가설** — 셸 레이어는 `absoluteFill`, 전환 애니메이션은 `translateX`뿐이라 근거 없음.
3. **재현 환경 구성** — 스토어 apk는 카카오·구글 로그인뿐이라 실계정 없이는 화면에 못 들어간다. 9월 개발 빌드는 그 뒤 추가된 네이티브 모듈(`ExpoTaskManager`)이 없어 JS가 뜨지 않았다. 그래서 로컬 Gradle로 개발 빌드를 새로 만들고(EAS 쿼터 미사용), 에뮬레이터를 S25 해상도(1080×2340, 450dpi, 제스처 내비)로 맞춰 개발용 이메일 로그인으로 실제 뽑기 화면을 띄웠다 → **동일하게 재현**.
4. **계측** — `onLayout` 로그를 층마다 심었다. 화면 루트 832(= 창 832, 정상) / 하단 영역 **58.7** / 버튼 줄 **18.1** / 버튼 **72.2**. 버튼 줄이 버튼보다 54dp 작았다 — 버튼이 줄 밖으로 넘친 것이다.
5. 첫 수정(스크롤에 `flex: 1`, 하단 `flexShrink: 0`)은 효과가 없었고, 이 수치가 그 이유(스크롤은 원인이 아님)를 바로 알려 줬다.

**원인**: 버튼 자체에 남아 있던 `flex: 1`. 세로 방향 래퍼 안에서 `flex: 1`은 `flexBasis: 0`이라 **높이 기준이 0**이 된다. Yoga는 높이가 자동인 래퍼의 크기를 이 기준으로 잡아 줄을 18dp로 계산했고, `minHeight: 72`인 버튼은 그 밖으로 넘쳤다. 웹(CSS flexbox의 min-height 자동 처리)은 결과가 달라 드러나지 않았다.

## 해결

버튼의 `flex: 1` 제거 — 폭은 래퍼가 나누고 버튼은 기본 `stretch`로 채운다. 같은 에뮬레이터 화면에서 두 버튼이 가격까지 보이고 제스처 바와 겹치지 않음을 캡처로 확인.

## 결과 (수치)

- 버튼 줄 18.1dp → 버튼 높이만큼 회복, 잘림 54dp → 0.
- 회귀 테스트: jest는 레이아웃을 계산하지 않으므로 원인 스타일을 직접 잠금(버튼 스타일에 `flex` 없음·`minHeight` 있음). `flex: 1`을 되돌리면 실패함을 확인.

## 배운 점 / 재발 방지

- "폭을 나누려는" `flex`가 교차축(높이)에서 기준 0을 만든다 — 비율 배분은 래퍼 한 곳에만, 안쪽 요소엔 주지 않는다.
- 웹 스모크로 같은 폭을 맞춰도 Yoga 차이는 못 잡는다. 레이아웃 제보는 **해상도를 맞춘 에뮬레이터 + `onLayout` 수치**로 판정하면 추측 수정(이번의 첫 수정)을 한 번에 걸러 낸다.
- 출시 앱에 로그인할 수 없을 때도 로컬 개발 빌드(개발용 로그인) + 딥링크로 실제 화면을 띄울 수 있다 — 단, 네이티브 모듈이 바뀌었으면 개발 빌드부터 새로 만들어야 한다.
