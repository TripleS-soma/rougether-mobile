# 서로 다른 개인 방을 한 집에 자연스럽게 보여주기

- 날짜: 2026-11-04 / 집 화면 / 앱 이슈 #1617, 검토용 PR 작성
- 키워드: 씬 합성, 좌표 정규화, 충돌 없는 레이아웃, 하위 호환

## 배경

습관 형성을 돕는 소셜 루틴 앱에서 루틴 수행과 방 꾸미기의 결과를 공동집에서도 보여주려 했다. 집 디자인 때문에 이탈한다는 의견은 있었지만, 이 작업에서 이탈 원인을 분석하거나 개선 효과를 측정하지는 않았다.

## 문제 (증상)

개별 방 전체를 새 집 그림 안에 넣으니 벽과 바닥, 원근이 서로 달라 붙여 넣은 느낌이 났다. 방 대신 가구만 배치한 첫 구성에서는 서로 다른 크기의 이미지가 겹쳤다.

## 원인 분석 (가설 → 검증 과정)

개인 방의 좌표와 배경을 유지하는 방식은 집 그림의 층 구조와 조화를 보장하지 못했다. 중심점 간 거리만 띄워도 가구 이미지의 실제 너비와 높이가 다르면 겹침을 막을 수 없었다. 따라서 개인 방의 배치 좌표를 공동집에 재사용하지 않고, 공동집 자체의 표현 규칙을 정의했다.

## 해결

가구 없는 개방형 집 그림을 제작하고, 현재 실제 배치한 가구 중 최대 2개와 캐릭터를 보여준다. 각 이미지는 서로 겹치지 않는 별도 사각형 안에서 contain으로 렌더한다. 화면을 누르면 기존 전체 방이 열린다. 4명보다 많은 집은 본채와 별채로 나누며, 화면 번호와 서버 membershipId를 분리해 방문 대상이 바뀌지 않게 했다.

기존 4종의 커버 키와 CDN 객체는 유지한다. 새 앱은 키를 번들 그림으로 해석하며, 신규 2종의 원격 PNG는 구버전의 투명 창문 규격에 맞췄다. 알 수 없는 키와 환경변수에 의한 되돌리기는 기존 경로를 사용한다.

## 결과 (수치)

6종을 실제 HouseScreen과 탐색 미리보기, 테마 선택기에 연결했다. 양쪽 좌석의 이미지 사각형이 겹치지 않는지 계산으로 확인하고, 1, 3, 4, 6, 10명에서 모든 membershipId가 방문 콜백에 보존되는지 테스트했다. Expo 웹 갤러리에서 6종 전환, 가구 숨김, 10명 별채와 개인 방 방문을 확인했다. 네이티브 기기나 운영 계정으로 검증한 결과는 아니다.

## 배운 점 / 재발 방지

개별 화면의 완성된 그림을 다른 장면에 재사용하면 경계와 원근도 함께 따라온다. 데이터는 재사용하되, 장면별로 필요한 시각 요소와 합성 규칙을 따로 정해야 한다. 겹침 방지는 대표 샘플에 대한 눈대중뿐 아니라 임의 종횡비에도 안전한 경계 조건으로 검증한다. 별채 간 직접 드래그 이동은 제공하지 않으며, 같은 별채 안의 기존 자리 교환 경로를 유지한다.

## 후속

마케팅 자료에서 같은 에셋을 재사용하도록 Storybook 카탈로그와 PNG, WebP 다운로드를 추가했다. 앱 번들에는 가벼운 WebP만 유지하고, 원본 PNG는 Storybook 정적 파일로 분리했다. Vite에서도 같은 에셋을 해석할 수 있도록 정적 이미지 import를 사용했다.

실제 Chromium 접근성 검사에서 accessible=false가 웹 이미지의 대체 텍스트를 만들지 않는 것을 확인했다. 장식용 가구와 이름 없는 배경에 빈 대체 텍스트를 지정한 뒤 새 스토리 7개의 렌더링과 접근성 검사를 통과했다. PNG 6개와 WebP 6개는 정적 빌드의 HTTP 응답과 manifest 해시를 대조했다.

## iOS TestFlight 후보 준비

공동집 변경의 dev OTA는 발행됐지만 기존 iOS TestFlight 설치본과 런타임 지문이 달랐다. 확인 당시 최신 production 빌드는 1.5.4의 129번이고, 기존 TestFlight 빌드는 1.5.3의 125번이었다. 스토어 버전 트레인 가드 때문에 같은 1.5.4로 새 후보를 만들 수 없어 1.5.5 후보를 준비했다.

이전 제출 도구는 115번 빌드 전용이었다. 이를 유지하면서 현재 후보의 빌드 ID, 앱 버전, 빌드 번호, 원본 소스와 런타임을 고정하는 별도 opt-in 제출 경로를 추가했다. EAS 업로드 완료와 Apple의 처리 완료를 구분하고, 불확실한 제출 결과에서 재제출하지 않고 기존 상태만 읽도록 했다. 실제 빌드와 제출 결과는 후속 배포 기록으로 확인한다.
