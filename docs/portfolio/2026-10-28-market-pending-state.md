# 구매 대기와 실제 보유 상태를 구분해 반복 구매 오류 줄이기

- 날짜: 2026-10-28 / 영역: 거래소 / 이슈: #1584
- 키워드: 비동기 주문, 조회 계약, 상태 전이, 캐시 무효화

## 배경

습관 형성을 돕는 소셜 루틴 앱에서 회원이 만든 가구를 지정가 주문으로 거래한다. 주문 접수와 엔진의 체결 처리가 분리돼 있다.

## 문제 (증상)

판매 주문이 없어 구매 주문이 대기 중인데도 상세 화면의 구매 버튼이 계속 활성화됐다. 사용자는 주문을 반복해서 시도했고 서버는 중복 구매를 거절했다.

## 원인 분석 (가설 → 검증 과정)

상세 화면은 인벤토리의 실제 보유 여부만 확인했다. 주문 접수는 미체결 구매 주문과 엔진 처리 전 접수까지 검사하므로 조회 응답과 접수 검증의 조건이 달랐다. 판매자 승인 절차는 없었고, 판매 주문이 없는 상태에서 구매 대기를 유지하는 엔진 동작은 정상이다.

## 해결

실제 보유 의미를 유지하면서 서버 상세 응답에 본인의 구매 및 판매 대기 여부를 추가했다. 화면은 대기 중 재구매를 막고 내 주문 확인 경로를 제공한다. 판매 주문이 없을 때 자동 체결 조건도 설명한다. 주문 처리 후에는 거래소 재조회를 기다린 뒤 주문 시트를 닫고, 다른 기기의 주문 등으로 중복 구매가 거절돼도 상세를 갱신한다.

## 결과 (수치)

구매 접수, 미체결, 취소와 체결 이후 상태 전이는 서버의 실제 DB 테스트로 검증했다. 앱은 대기 상태의 버튼, 안내 및 내 주문 이동을 컴포넌트 테스트로 확인한다. 운영 배포 및 실기기 검증 결과는 이 기록에 포함하지 않는다.

## 배운 점 / 재발 방지

비동기 작업의 상태를 최종 결과로 치환하면 안 된다. 구매 대기를 보유로 표시하면 판매 버튼까지 잘못 열릴 수 있다. 조회 화면에는 중간 상태를 분리해 전달하고, 서버의 최종 검증은 그대로 유지한다.
