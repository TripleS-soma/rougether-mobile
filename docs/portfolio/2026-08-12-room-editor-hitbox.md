# 방 꾸미기에서 엉뚱한 가구가 잡히던 문제 — 정사각 터치 박스의 투명 모서리와 선택 무관 드래그

- 2026-08-12 / room / #767, PR #768 (후속: PR #1238)
- 키워드: 히트 테스트, 겹친 객체 선택(z-order), 투명 영역, 터치 타깃(44pt), 제스처 게이팅(react-native-gesture-handler), 음수 hitSlop

## 배경

Rougether의 방 꾸미기는 작은 캔버스 편집기다. 방 이미지 위에 가구 PNG를 자유 배치하고, 한 번 탭해 선택한 뒤
드래그로 옮기고, 핀치나 모서리 핸들로 크기를 조절하고, 툴바로 회전·반전·앞뒤 순서를 바꾼다. 가구는 z 오름차순으로
그려지고, 각 가구의 터치 영역은 `방 너비 × 0.28` 크기의 **정사각형 박스**(360px 방에서 약 101px)였다.

## 문제 (증상)

사용자 제보는 이랬다.

> 방 꾸미기에서 내가 지금 포커스한 이미지뿐만 아니라 다른 이미지도 터치가 겹치면 움직여서 배치가 불편해

가구가 몰린 곳에서 특히 심했다. 눈으로는 아래 러그를 잡았는데 실제로는 위에 있는 램프가 끌려갔다. 방금 선택한 가구를
옮기려 해도 손가락이 이웃 가구의 박스에 걸치면 이웃이 움직였다.

## 원인 분석 (가설 → 검증 과정)

처음엔 "터치 영역이 너무 크다" 하나로 보였다. 코드를 따라가 보니 원인이 두 겹이었다.

1. **선택과 조작이 분리돼 있지 않았다.** `selected`는 선택 링과 크기 핸들을 그리는 데만 쓰였고, 팬(드래그) 제스처는
   **모든 가구에 조건 없이** 붙어 있었다. 그래서 A를 선택해 놓아도 손가락 아래에 있는 가구가 움직였다. 이 상태에서 "선택"은
   시각 표시일 뿐 입력 라우팅에는 영향이 없었다.
2. **히트 영역이 그림이 아니라 박스였다.** 터치 영역이 `itemW × itemW` 정사각형이라, 가구 PNG의 투명 여백까지 터치를
   받았다. 가구 아트는 대부분 박스를 다 채우지 않는다(램프·화분처럼 가늘거나 둥근 것이 많다). 박스가 겹치면 히트 테스트는
   z가 높은 쪽을 고르므로, **보이지 않는 위 가구의 투명한 모서리가 보이는 아래 가구를 가렸다.**

두 원인 중 하나만 고치면 부족했다. 1만 고치면 "탭으로 선택"하는 단계에서 여전히 투명 모서리 때문에 엉뚱한 가구가
선택된다. 2만 고치면 선택해 둔 가구를 옮기다가 이웃을 건드리는 문제가 남는다.

## 해결

**1) 선택된 가구만 조작을 받게 했다.** 팬에 `.enabled(selected)`를 걸어 선택된 가구만 움직이게 했다. 선택 안 된 가구는
탭(=선택)만 받는다. 핀치(크기 조절)도 같은 이유로 함께 막았다. 이동만 막고 크기 조절을 열어 두면 겹친 이웃이 의도치
않게 커지는 같은 사고가 남기 때문이다. 결과적으로 편집 흐름은 "탭으로 고르고 → 고른 것만 조작"이 됐다. 데스크톱
디자인 툴이 클릭 선택과 드래그를 다루는 방식과 같다.

**2) 터치 영역을 안쪽으로 줄였다.** 음수 `hitSlop`으로 각 변을 깎아 박스 안쪽 **78%**만 터치를 받게 했다
(`HITBOX_RATIO = 0.78`). 줄이기만 하면 가장 작게 줄인 소품을 못 집는 문제가 생긴다. 계약상 최소 축척은 0.5이고,
여기서 78%로 줄이면 39px쯤이라 권장 터치 크기 44pt보다 작아진다. 그래서 **44pt 하한**(`MIN_HIT_SIZE`)을 뒀다. 깎는 양은
순수 함수로 분리했다.

```ts
export function hitSlopInset(boxSize: number): number {
  const target = Math.max(MIN_HIT_SIZE, boxSize * HITBOX_RATIO);
  return Math.max(0, (boxSize - target) / 2);
}
```

같은 인셋을 팬·탭·핀치 세 제스처에 똑같이 적용했다. 선택 판정(탭)과 조작 판정(팬·핀치)이 서로 다른 영역을 보면
또 다른 어긋남이 생기기 때문이다.

**트레이드오프 (PR에 명시)**

- 다른 가구를 옮기려면 이제 항상 "탭 → 드래그" 두 단계다. 선택 안 된 가구에서 드래그를 시작하면 아무것도 움직이지
  않고, 손을 떼면 탭이 성립해 선택된다. 실기기에서 답답하면 "선택된 것을 임시로 최상위 z로 올리기" 쪽으로 바꿀 수
  있게 대안을 남겨 뒀다.
- 78%는 **눈대중으로 정한 상수**다. 가구 19종의 실제 아트 여백을 재서 정한 값이 아니다. 아트가 박스를 꽉 채운 가구는
  가장자리가 잡히지 않고, 여백이 큰 가구는 투명 영역이 여전히 조금 남는다. 정확히 하려면 가구별 히트박스 메타데이터가
  필요해서 이번 범위에서 뺐다.

**후속: 웹에서 가구를 아예 못 고르던 문제 (PR #1238, 2026-09-09)**

선택 전 팬을 `enabled(false)`로 둔 채 `Gesture.Exclusive(pan, tap)`으로 묶어 두었는데, 웹 RNGH 오케스트레이터는 비활성
핸들러를 "아직 끝나지 않은 핸들러"로 보고 탭을 계속 기다렸다. 그래서 데스크톱 웹에서는 가구를 탭해도 선택이 되지
않았다. 네이티브는 비활성 인식기를 실패로 처리해서 이 문제가 드러나지 않았다. 해결로 선택 전에는 제스처를 **탭 하나만
조합**하게 바꿨다(`selected ? Simultaneous(Exclusive(pan, tap), pinch) : tap`). 같은 의도("선택 전엔 탭만")라도
"비활성 핸들러를 두는 것"과 "핸들러를 아예 조합하지 않는 것"은 플랫폼마다 다르게 동작할 수 있었다.

## 결과 (수치)

- 360px 방 기준 가구 박스 101px → 터치 영역 약 79px(한 변). 넓이로 보면 0.78² ≈ 61%만 남고, 가장자리 약 39%가 터치에서
  빠진다(계산값).
- 44pt 하한: 박스 50px → 44px, 44px 이하 박스는 깎지 않는다(단위 테스트로 고정).
- PR #768 시점 4종 체크(typecheck·lint·format·test) 통과, 전체 테스트 793개. 리뷰 반영 후 PR 코멘트 기준 45건 통과(어느 범위의 실행인지는 코멘트에 적혀 있지 않다).
- 회귀를 막는 테스트:
  - `src/components/room/__tests__/draggable-furniture.test.ts`: `hitSlopInset` 4건(78% 수축, 44pt 하한, 44 이하 미수축,
    항상 0 이상이라 영역이 넓어지지 않음).
  - `src/components/screens/__tests__/room-decor-screen.test.tsx`: "선택 안 된 가구는 팬·핀치를 받지 않는다"(좌표·스케일이
    처음 그대로인지 단언), "선택 전 가구의 제스처는 탭뿐"(선택 전 팬·핀치 핸들러 미등록, 선택 후 등록).
- 리뷰 과정에서 얻은 것: 처음엔 "선택된 상태에서 여전히 움직인다"만 테스트했고, **반대 케이스**(선택 안 된 가구는
  움직이지 않는다)가 빠져 있었다. 이 핵심 한 줄(`.enabled(selected)`)을 지워도 실패하는 테스트가 없었으므로, 자동 리뷰의
  지적을 받아 추가했다. 기존 꾸미기 테스트 3건은 선택 없이 제스처를 쏘고 있어서, 앞에 `tapItem`을 넣어 새 계약에 맞췄다.

## 배운 점 / 재발 방지

- **겹친 객체 선택은 "누가 위에 있나"만으로 풀리지 않는다.** z-order 히트 테스트는 투명 영역도 "위에 있는 것"으로 친다.
  보이는 것과 잡히는 것을 맞추려면 히트 영역을 실제 그림 쪽으로 좁혀야 한다.
- **선택 상태를 입력 라우팅의 게이트로 쓴다.** 선택이 시각 표시에만 머물면, 사용자가 고른 대상과 실제 조작 대상이 달라진다.
- **좁히는 쪽에는 하한이 필요하다.** 투명 여백을 줄이는 최적화가 작은 객체를 못 집게 만드는 회귀로 이어지지 않게, 44pt
  하한을 순수 함수와 단위 테스트로 고정했다.
- **"비활성"과 "없음"은 다르다.** 같은 제스처 조합이 네이티브와 웹에서 다르게 동작했다. 조건부 입력은 비활성 핸들러를
  두기보다 조합 자체를 바꾸는 편이 플랫폼 간에 안전했다.
- **다음 단계 아이디어 (아직 하지 않음):** 일률 78%는 근사치다. 가구 PNG의 알파 채널로 마스크(또는 다운샘플한 알파
  비트맵이나 가구별 히트 폴리곤)를 만들어 두고, 터치 좌표를 회전·반전·스케일의 역변환으로 가구 로컬 좌표로 옮긴 다음
  그 픽셀이 불투명한지 보는 **알파 마스크 픽셀 히트 테스트**가 정석이다. 겹친 후보를 z 내림차순으로 훑어 처음 불투명한
  것을 고르면 된다. 이 방식은 카탈로그에 마스크 생성 파이프라인이 필요하고, 제스처 시작 시점(UI 스레드)에 판정해야 하는
  비용이 있어서 이번에는 상수 비율로 타협했다.
