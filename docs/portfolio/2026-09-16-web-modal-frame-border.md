# 웹 바텀시트 양옆 검은 선 — RN Modal이 앱 프레임 밖에 붙는 문제

- 2026-09-16 / design(웹앱) / #1367, #1368
- 키워드: React Native Web, Modal 포털, 반응형 레이아웃, 디자인 토큰, 브라우저 실측(getComputedStyle)

## 배경

같은 코드베이스를 iOS·Android·웹(PWA)으로 낸다. 화면은 폰 기준으로 설계돼 있어, 넓은 데스크톱 창에서는 앱을 중앙 480px 컬럼(창 960px 이상이면 2단 1200px)에 가두는 `AppFrame`을 쓴다.

## 문제 (증상)

웹에서 루틴/투두 작성 시트를 열면 시트 양옆에 **검은 세로선 두 줄**이 보이고, 넓은 창에서도 시트가 폰 폭에 갇혀 왜소했다. 사용자 확인 결과 작성 시트뿐 아니라 **모든 바텀시트**에서 같았다.

## 원인 분석

1. 브라우저에서 시트를 열고 `getComputedStyle`로 시트 래퍼를 실측: 폭 480, `border-left-width: 1px`, `border-left-color: rgb(0,0,0)`.
2. 시트는 공용 `BottomSheet` → `ModalFrame` 한 경로를 지난다. `ModalFrame`이 앱 프레임용 스타일(`innerFramed`: 폭 480 + 양옆 hairline 테두리)을 재사용하고 있었다.
3. 앱 프레임은 테두리 색을 토큰(`borderColor: t.border`)으로 따로 넘기는데, **RN Modal은 프레임 밖 body에 포털로 붙어** 색 지정 없이 테두리 폭만 적용 → 기본 검정.
4. 수정 전(dev 원본)으로 되돌려 같은 조건에서 대조 실측해 원인을 확정했다.

## 해결

`ModalFrame` 전용 스타일로 분리했다. 폰 컬럼 창(480~959px)은 폭 480 유지·테두리 없음, 2단 창(960px+)은 새 토큰 `SHEET_FRAME_MAX_WIDTH`(640)까지 넓힌다. 웹에서 동적 width 값이 하이드레이션과 겹쳐 DOM에 안 실렸던 과거 함정을 피하려고 폭은 정적 StyleSheet 항목으로 뒀다. 공용 경로 한 곳 수정으로 앱의 모든 바텀시트에 반영됐다.

## 결과 (수치)

- 창 1512px 실측: 시트 폭 480 → 640, 좌우 border 1px 검정 → 0
- 작성·루틴 메뉴·재화 내역 시트 3종에서 동일 확인, 관련 테스트 46 suites 통과

## 배운 점 / 재발 방지

- 포털로 렌더되는 요소(Modal·Toast)는 부모 레이아웃의 스타일 컨텍스트를 물려받지 않는다. 스타일 재사용 시 "어디에 마운트되는가"를 본다.
- 웹 레이아웃 버그는 스크린샷보다 `getComputedStyle` 수치 + 수정 전/후 대조가 빠르고 확실하다.
