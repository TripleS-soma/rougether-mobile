# 병렬 i18n 마이그레이션 마무리 — 1,400+ 키를 충돌 없이 나눠 끝내기

- 2026-09-14 ~ 2026-09-16 / member(앱 전반) / #893, #1345·#1348·#1353~#1356·#1359·#1360(1·2단계), #1375·#1380~#1384(마무리)
- 키워드: react-i18next, 대규모 리팩터링 분할, 병렬 PR·git worktree, TDZ, WebView 문자열 주입, 헤드리스(위젯) 컨텍스트 i18n

## 배경

한국어 전용으로 출시된 앱을 영어권 출시(#1369) 전제로 영어 지원한다. 조사 시점 사용자 노출 한국어 문자열은 약 1,100건, 72개 파일 이상에 퍼져 있었다. 1인 개발이라 리뷰 가능한 크기로 쪼개야 했고, 매일 기능 PR이 계속 머지되는 중이었다.

## 문제

1. **규모와 충돌**: 도메인별로 나눠 병렬로 진행하면 모두가 같은 `ko.json`/`en.json`을 수정해 머지 충돌이 매번 난다.
2. **런타임 크래시 위험**: 한 PR(#1349)이 CI에서 `TS2448 Block-scoped variable 'tr' used before its declaration`으로 실패. 자동 리뷰가 "로그인한 모든 사용자가 앱을 열자마자 크래시"로 판정 — `useCallback` 의존성 배열에 `tr`을 넣었는데 `const tr = useT()` 선언은 훨씬 아래에 있어 렌더 시 TDZ(Temporal Dead Zone) 에러.
3. **i18n이 닿지 않는 곳**: 미니게임은 WebView 안의 HTML 문자열이라 앱 i18n 인스턴스에 접근할 수 없고, Android 홈 위젯은 앱과 별개로 실행되는 헤드리스 태스크라 현재 언어를 알 수 없다.
4. **"번역하면 안 되는" 한국어 구분**: 서버 카테고리 이름·뽑기 등급처럼 서버 값과 매칭하는 데이터 키, 저장되는 값, 브랜드명이 문구와 섞여 있다.

## 원인 분석 · 설계 판단

- 충돌의 원인은 "도메인 분할"이 코드엔 있는데 리소스 파일엔 없었던 것. 코드 파일 소유와 리소스 파일 소유를 1:1로 맞추면 병렬 PR이 서로 닿지 않는다.
- TDZ는 타입체커가 잡았지만, 병렬 작업 중 하나만 멈춰 이틀 방치되며 dev와 충돌까지 쌓였다 → 멈춘 PR은 리베이스보다 **최신 dev에서 재작업**하는 편이 싸다고 판단.
- WebView·위젯은 "번역을 실행 환경으로 가져간다"가 아니라 "앱이 번역된 결과(또는 언어 코드)를 실어 보낸다"로 풀 수 있다.

## 해결

1. **리소스를 도메인 파일로 분리**(#1348): `resources/{ko,en}/<domain>.json`을 `index.ts`가 병합. 최상위 키가 겹치면 병합에서 조용히 사라지므로 "병합 키 수 = 파일별 키 수 합" 테스트를 추가. 이후 도메인 PR 5개를 병렬로 냈다.
2. **CI 가드**: ko/en 키 누락·빈 값·보간 변수 불일치를 막는 테스트(#1345)로 번역 누락이 머지되지 않게 함.
3. **마무리 5갈래를 git worktree로 격리해 병렬 진행**: 담당 파일 목록과 담당 리소스 파일을 겹치지 않게 명시해 서로 충돌 없이 PR 5개를 동시에 올림. 멈췄던 #1349는 닫고 dev 기준으로 재작업(#1382), `useT()` 선언을 사용처 위로 올려 TDZ 제거.
4. **미니게임(#1384)**: HTML 생성 시점에 현재 언어의 원문 사전을 JSON 이스케이프 경로로 주입하고, 문서 내부 `fmt()`가 `{{score}}` 자리표시자를 채움. 게임 규칙·점수·엔진 파일은 diff 0으로 유지(서버 검증기와 맞물려 있음). 영어 문서에 한글 0자, 두 언어 모두 스크립트 파싱 성공을 테스트로 고정.
5. **Android 위젯(#1381)**: 앱이 위젯 요약을 저장할 때 언어 코드를 함께 저장하고, 위젯 태스크가 그 언어로 `i18n.t`를 조회(앱의 현재 언어는 건드리지 않음). iOS 위젯은 Swift 변경이 네이티브 빌드를 요구하므로 요약에 `lang`만 미러해 두고 다음 네이티브 윈도우로 분리.
6. **데이터 키 분류 원칙**: 서버 값과 매칭하는 문자열(카테고리 id, 등급)은 유지하고 표시만 번역. 서버가 한국어로 내려주는 집 커버 이름은 커버 키로 영어 이름을 찾고 모르면 서버 이름으로 폴백(#1383). 영어 스크린샷에서 한국어로 드러난 테마·폰트 브랜드명은 표시명만 번역하고 저장 id는 불변(#1380).
7. 서버가 완성문으로 내려주는 문구(알림·푸시·추천·주간 회고 프롬프트·봇)는 앱에서 풀 수 없어 서버 이슈(rougether-server#392)로 분리하고 위치를 실측해 넘김.

- 마무리 5갈래 PR 동시 진행, 리소스 파일 충돌 0.

## 배운 점 / 재발 방지

- 대규모 수평 변경은 **소유권(코드·리소스)을 먼저 쪼개는 인프라 PR**이 병렬화의 전제다.
- React 훅에서 `useCallback` deps에 새 값을 넣을 땐 선언 순서를 본다. 타입체커(TS2448)가 잡아주므로 CI 타입체크가 필수 게이트여야 한다.
- 멈춘 PR은 충돌을 풀기보다 최신 브랜치에서 다시 만드는 게 빠를 때가 많다.
- "번역"은 문자열 치환이 아니라 **어디서 실행되는가(WebView·헤드리스·서버)** 와 **그 문자열이 데이터인가 문구인가**를 먼저 분류하는 일이다.

- 인트로 화면 텍스트에 한국어 "Google 계정으로 로그인"이 잡혔지만, 화면 밖에 숨겨 둔 구글 공식 버튼(aria-hidden, 팝업을 여는 용도)이라 사용자 노출이 아님을 코드로 확인.
