# Expo Web 전체 UI 스모크 + UX 감사

같은 폴더의 `smoke.js`(기능 스모크)와 `ux-audit.js`(UX 감사)가 실행 본체다.
실서버(dev API)를 치므로 결과는 목이 아니라 진짜 동작이다.
"동작하나?"는 smoke, "잘 보이고 잘 눌리나?"는 ux-audit.

## 실행 절차

1. **dev 서버**: `npx expo start --web --port 8081` 백그라운드 실행 후 포트 폴링
   (`until curl -sf http://localhost:8081; do sleep 2; done`). 이미 떠 있으면 재사용.
2. **Playwright 준비**(세션 스크래치패드 등 프로젝트 밖 폴더에서):
   `npm init -y && npm i playwright && npx playwright install chromium`.
   프로젝트 node_modules를 오염시키지 말 것.
3. **실행**: 준비 폴더에 `smoke.js`를 복사한 뒤 `node smoke.js`.
   exit 0 = 전부 통과. 스크린샷은 실행 폴더의 `shots/`에 스텝 순서대로 쌓인다.
4. **판정**: RESULTS의 FAIL 여부 + CONSOLE ERRORS + NETWORK FAILURES(4xx/5xx 포함)를
   함께 본다. FAIL이면 해당 `NN-이름-FAIL.png`를 **직접 열어** 앱 버그인지
   셀렉터 드리프트인지 구분한다.

## 로그인 규칙 (사용자 지정)

- **이메일 칸에 `4`, 비밀번호는 아무 값** → userId 4 고정 dev 계정으로 로그인.
- 비밀번호가 비어 있으면 제출이 막힌다(`canSubmit = password.length > 0`) — 아무거나 채울 것.
- 이메일을 비우면 매번 새 계정이 생성돼 dev 서버가 오염된다. 새 계정 플로우
  (온보딩 포함)를 테스트할 때만 비우고, 평소엔 4를 쓴다.

## 스크립트가 이미 처리하는 것

- 온보딩 분기: 계정 4는 온보딩 완료 상태라 자동 스킵, 새 계정이면 목표/캐릭터 선택 진행.
- 루틴 완료 토글은 **켰다가 다시 꺼서** 계정 4 데이터를 원상복구한다.
- 집 탭은 빈 상태/집 보유 상태 둘 다 허용(`아직 함께하는 집이 없어요` or `우리 그룹의 미션`).
- 스텝 실패해도 계속 진행 — 커버리지 리포트가 목적.

## 셀렉터 드리프트 주의

스텝이 깨지면 대부분 UI 문구/라벨 변경이다. 현재 의존하는 앵커:
로그인 placeholder `이메일`/`비밀번호`, 탭 라벨 `나의 방`/`집`/`설정`,
`집 탐색`(라벨), `온보딩 다시 보기`, 꾸미기 `적용하기`, `뽑기 상점`(라벨), `가챠`.
문구를 바꾼 PR이면 smoke.js도 같이 고칠 것.

## UX 감사 (ux-audit.js)

스모크와 같은 준비(서버 + Playwright 폴더) 후 `node ux-audit.js`. 4개 컨피그
(라이트/다크 × 390/320px)마다 **새로 로드**해(동적 테마 전환은 리페인트가
불안정) 로그인 후 주요 7개 화면을 걷고 화면별로 검사한다:

| 검사          | 기준                                                         | 잡아낸 실제 버그               |
| ------------- | ------------------------------------------------------------ | ------------------------------ |
| 텍스트 대비   | UNREADABLE < 1.8:1(즉시 조치) / aa-fail < 3:1 / warn < 4.5:1 | #229 다크모드 집 타일 (1.03:1) |
| 텍스트 잘림   | ellipsis 걸린 채 scrollWidth > clientWidth                   | #227 320px 헤더 닉네임         |
| 가로 오버플로 | 페이지 scrollWidth > viewport                                | —                              |
| 터치 타깃     | 24×24px 미만 (hitSlop은 DOM에 없어 보수적)                   | —                              |
| 라벨 누락     | 버튼에 aria-label도 텍스트도 없음                            | —                              |

**판정 기준**: UNREADABLE은 0이어야 한다(전부 나열됨 — 발견 즉시 이슈).
aa-fail은 대부분 브랜드 컬러 시스템성 이슈(흰 글자+primary 버튼 ≈2.7:1,
warning 스트릭 ≈2.2:1, primary 탭 라벨 ≈2.5:1 — 이슈 #232로 추적)라 새로
늘었는지만 본다. warn은 카운트만(대부분 textMuted).

**노이즈 필터 내장**: 이모지(색상 미적용 렌더)와 Ionicons 글리프(PUA 문자)는
텍스트로 세지 않는다. 새 검사를 추가하면 반드시 알려진-버그 코드로 한 번
역검증할 것(이 감사기는 #229/#227 수정 전 코드에서 두 버그를 정확히 잡고,
수정 후 0이 되는 것으로 검증됨 — 2026-07-09).

**web 한정 한계**: `adjustsFontSizeToFit`은 RN-web 미지원이라 320px에서
"…의 방" 헤더가 여전히 clipped로 잡힌다(네이티브에선 폰트 축소로 해결됨,
#228). web 리포트에서 이 항목은 무시.
