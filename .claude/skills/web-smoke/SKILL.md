# Expo Web 전체 UI 스모크

같은 폴더의 `smoke.js`(Playwright)가 실행 본체다. 실서버(dev API)를 치므로 결과는
목이 아니라 진짜 동작이다.

## 실행 절차

1. **dev 서버**: `npx expo start --web --port 8081` 백그라운드 실행 후 포트 폴링
   (`until curl -sf http://localhost:8081; do sleep 2; done`). 이미 떠 있으면 재사용.
2. **Playwright 준비**(세션 스크래치패드 등 프로젝트 밖 폴더에서):
   `npm init -y && npm i playwright && npx playwright install chromium`.
   프로젝트 node_modules를 오염시키지 말 것.
3. **실행**: 준비 폴더에 `smoke.js`를 복사한 뒤 `node smoke.js`.
   exit 0 = 전부 통과. 스크린샷은 실행 폴더의 `shots/`에 스텝 순서대로 쌓인다.
4. **판정**: RESULTS의 FAIL 여부 + CONSOLE ERRORS + NETWORK FAILURES(4xx/5xx 포함)를
   함께 본다. FAIL이면 해당 `NN-이름-FAIL.png`를 **직접 열어** 앱 버그인지
   셀렉터 드리프트인지 구분한다.

## 로그인 규칙 (사용자 지정)

- **이메일 칸에 `4`, 비밀번호는 아무 값** → userId 4 고정 dev 계정으로 로그인.
- 비밀번호가 비어 있으면 제출이 막힌다(`canSubmit = password.length > 0`) — 아무거나 채울 것.
- 이메일을 비우면 매번 새 계정이 생성돼 dev 서버가 오염된다. 새 계정 플로우
  (온보딩 포함)를 테스트할 때만 비우고, 평소엔 4를 쓴다.

## 스크립트가 이미 처리하는 것

- 온보딩 분기: 계정 4는 온보딩 완료 상태라 자동 스킵, 새 계정이면 목표/캐릭터 선택 진행.
- 루틴 완료 토글은 **켰다가 다시 꺼서** 계정 4 데이터를 원상복구한다.
- 집 탭은 빈 상태/집 보유 상태 둘 다 허용(`아직 함께하는 집이 없어요` or `우리 그룹의 미션`).
- 스텝 실패해도 계속 진행 — 커버리지 리포트가 목적.

## 셀렉터 드리프트 주의

스텝이 깨지면 대부분 UI 문구/라벨 변경이다. 현재 의존하는 앵커:
로그인 placeholder `이메일`/`비밀번호`, 탭 라벨 `나의 방`/`집`/`설정`,
`집 탐색`(라벨), `온보딩 다시 보기`, 꾸미기 `적용하기`, `뽑기 상점`(라벨), `가챠`.
문구를 바꾼 PR이면 smoke.js도 같이 고칠 것.
